# Engine workflow review after the November 19 repairs

The eight high-priority cases in the [first review](2026-11-19-engine-workflow-review.md#repair-status) each passed a focused regression in this review. The most consequential new cases are an Editor navigation that saves changes into the wrong Prefab, a source-carrying Export that omits a later level's image, and a Cook that verifies current sidecar bytes while delivering stale content. The Editor case reached the saved file. Both delivery cases reached a relocated loader or the decoded cooked asset.

The review began at `f222889e6e5a` on `refactor/foundation`. The split-view repair under review landed at `8364fa1`, followed by its qualification record at `706ba10fb164`. The follow-up records six P1 findings, nine P2 findings, one narrower input defect and one open HUD policy choice. References below use the local Bevy checkout at `779770720e6a` and Godot at `b070e63b161a`. Severity reflects the effect on a supported consumer.

## P1 findings

### Opening a Scene anchor for Prefab A can silently edit and save Prefab B

**Reproduced from the Project Browser through Save on disk.** The Scene references `StableId(A)`. Change the Prefab sidecar at the same path to B, then open that file through the Browser. Switch back to the Scene, select its original anchor, and run `OpenPrefabSource`. The command succeeded, activated B's existing tab and emitted no diagnostic. Adding `edit-intended-for-A` and saving returned `Saved`, cleared the dirty flag and wrote that entity to the file with B's sidecar. The Scene still referenced A. In a separate run, changing the sidecar back to A before Save produced `SourceBindingMismatch`. Restoring B let the same dirty draft save. The recent Save guard correctly enforces the identity it is given. [Browser identity admission](../../src/project_host/authoring/document.rs#L439) · [Anchor resolution](../../src/project_host/runtime/editor/persistence.rs#L769) · [Existing tab activation](../../src/project_host/runtime/editor/persistence.rs#L263) · [Save source selection](../../src/project_host/runtime/editor/persistence.rs#L185)

Carry the resolved Prefab's expected `SourceDocumentKey` through navigation. Check it when reusing a tab and when admitting a newly opened document. A mismatch should keep the Scene active and preserve the existing Prefab draft. Extend the existing same-source Browser reuse test with the A/B case and a same-key success control. This repair belongs at the first point where the requested and opened identities can diverge. [Existing reuse test](../../src/project_host/runtime/tests/document_sources.rs#L163)

### An exhausted task handle discards another task's successful result

### Optional audio observation can terminate ordinary cooked playback

**Source-traced Player path, with an executed callback control.** The `audio-desktop` cooked Player always enables callback capture, including interactive play where the copied PCM is discarded. At 48 kHz stereo the 1,024 slots of 512 samples can hold at most 5.46 seconds before a drain. Partly filled chunks reduce that interval. If the device keeps running while the Player thread stalls past that capacity, capture overflow permanently closes playback admission. The callback cancels voices and the Player reports failure on its next poll. The existing CPU callback test passed when rerun. It fills a one-slot capture, observes silence, and verifies that a subsequent cue is refused. [Cooked recipe](../../samples/two-level-game/src/audio.rs#L103) · [Capacity](../../samples/two-level-game/src/audio/device.rs#L25) · [Overflow and cancellation](../../samples/two-level-game/src/audio/device.rs#L858) · [Player drain](../../samples/two-level-game/src/bin/player_audio/observation.rs#L67) · [Executed test](../../samples/two-level-game/src/audio/device_tests.rs#L620)

The sample documents continuous capture as the cost of this placement. For interactive playback, either disable PCM observation or count discarded capture frames while continuing to mix. Strict continuity remains useful in `--verify`. Exercise a stalled observer with a live cue under both policies. Godot's capture effect writes output before deciding whether to retain a copy and counts discarded observation frames. [Placement policy](../../samples/two-level-game/README.md#L306) · [Godot capture](https://github.com/godotengine/godot/blob/b070e63b161aa816afac71dcfc9d60859d38f220/servers/audio/effects/audio_effect_capture.cpp#L121)
