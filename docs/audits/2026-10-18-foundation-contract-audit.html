Scope and confidence

This audits foundational contracts, not missing Tilemap, save, physics, audio, or animation features. It does not promise an architecture without future debt.

The directions below are proposals. An Accepted ADR remains authoritative until revised; this report does not silently approve a new contract.

P1 means repair an existing defect or settle a contract before expanding its consumers. P2 means close a bounded seam with its named consumer, or measure a scale assumption. Priority is not evidence that a runtime failure has been reproduced.

Confirmed defect: failing regression exists. Structural contract risk: source establishes a mismatch or coupling; static examples are labeled. Scale assumption: correct work grows with world size; no unmeasured frame-budget failure is claimed.

Dependency paths

Work can proceed in independent lanes. There is no single mandatory rewrite sequence.

Immediate owner defects · F01 + F02

Repair asset context and glyph ownership independently. Regressions pass in the focused suite; consumer/native verification remains in progress.

Values and editing · F03 transaction boundary first; co-design F04 + F05

Correct final-candidate validation first. Design recursive shape and effective reference semantics together, then integrate their final closure. Keep structural checks per operation.

Reusable worlds · F06 → F07

Separate durable identity from runtime incarnation before proving unload/reconcile with independent physics and audio owners.

Execution · F09 → F08 → F10

Establish thread ownership; add managed substeps when a real consumer needs them; settle current-pose reads through that consumer.

Presentation prerequisites · F15 / F13 / F14 / F16

Preserve endpoints before multi-device input; shared stages before multipass runtime/Editor; device profile before optional capabilities; shared font owner before custom-font presentation.

Measured scale · authority → F11; budget → F12

Keep invalidation trustworthy before reducing hierarchy validation. Trigger transform optimization with a representative budget, not file size or type counts.

F01 · Advanced scene replacement loses admitted asset context

P1Confirmed defectFixedHigh confidence
Evidence
Baseline nara_scene/spawn.rs:1034–1052 prepares replacement with database = None. Regression: product_replacement_preserves_stable_asset_resolution.
Counterexample
Initial spawn resolves a stable asset UUID; advanced in-game replacement/Retry of the same content fails. This does not describe Editor Restart.
Direction
Explicitly borrow the replacement database/context. StartupSceneSourceView borrows the complete admitted source through its existing retention owner; do not add another authority owner.
Migration
Scene replacement APIs, startup source/view plumbing, reference-game Retry, direct callers and tests.
Prerequisite
None. Preserve source-retention ownership and atomic document semantics.
Acceptance
Failing baseline regression becomes green; UUID/path references agree at initial spawn and replacement; rejection preserves the old product. Focused regressions pass; startup/reference consumers remain pending.

F02 · Private glyph atlases collide in a shared GPU cache

P1Confirmed defectFixedHigh confidence
Evidence
nara_render_wgpu/texture.rs:266 derives shared cache identity from values private to each atlas. Distinct owners can start at font revision 1, page 0, generation 1.
Counterexample
Two targets, or two planners for the same target, produce different atlas pixels with equal GPU keys. A later packet can reuse the wrong texture.
Direction
Use a checked private atlas incarnation plus page revision. Snapshot clones preserve identity; font/reset establishes a new owner incarnation.
Migration
UI atlas/packet ownership, GPU cache keys, target switching, planner reuse, retirement and device-recreation tests.
Prerequisite
None; independent of F01 and the custom-font contract in F16.
Acceptance
Cross-target and same-target/cross-planner regressions pass; unchanged snapshots reuse uploads; reset retires the prior owner. Focused library/GPU checks pass; this is not complete native Editor qualification.

F03 · Patch transactions validate business invariants between operations

P1Structural contract riskProposedStatic counterexample
Evidence
patch.rs:260, :377–408, :1197 validate intermediate documents; validation.rs:287 reaches native invariants. No new regression was executed for this entry.
Counterexample
An invariant requires x == y. Two field operations changing (1,1) to (2,2) fail in either order despite a valid final candidate.
Direction
Check paths, permissions, shape and work budgets per operation. Apply business/component/reference closure once to the final candidate before publication.
Migration
Scene/prefab patch preparation, registry validation entry points, inverse/undo coverage, Editor patch consumers.
Prerequisite
Align effective values and reference closure with F04/F05. Correct the transaction boundary without waiting for a generic framework.
Acceptance
Coupled-field patches work in either order; invalid final state fails atomically; bad paths and excessive work still fail; inverse application restores both scene and prefab documents.

F04 · Flat field paths cannot describe variable-container references

P1Structural contract riskProposedHigh confidence
Evidence
schema.rs:472 and registry.rs:2462 expose flat fields and opaque Map/List kinds. entity_reference.rs:191 checks against fixed absolute declared reference paths.
Counterexample
A variable Vec<EntityRef> cannot declare every runtime element using fixed paths. Derive syntax alone cannot close serialization, remapping, migration and Inspector access.
Direction
Bounded recursive shape, matching field locators, reference visitors, lineage and fingerprints must migrate together. Avoid arbitrary validation DSLs or speculative stable list-element identity.
Migration
Reflect schema/registry/derive and export, asset/entity visitors, compatibility, scene/prefab rewriting, Editor field operations.
Prerequisite
Co-design F05; settle before broad collection authoring. F03 validates the resulting final effective value.
Acceptance
Nested references round-trip, remap, validate and export with one schema; traversal limits bound work; incompatible shape changes affect fingerprints/migrations; scalar schemas migrate explicitly.

F05 · Reference validity differs across admission, export and defaults

P1Structural contract riskProposedHigh confidence
Evidence
Baseline scene/tests.rs:3718 admits a missing local reference that fails export; scene/tests.rs:1263 rejects during prefab expansion. Default handling at registry.rs:2435 differs from asset_reference.rs:167 / entity_reference.rs:223 visitation.
Counterexample
Equivalent data is accepted through one entry and rejected through another. An omitted non-null default reference can escape reference visitation.
Direction
Separate required presence from target existence, and local/durable/unloaded/deleted semantics. Normalize one effective value including defaults, then use one reference closure contract.
Migration
Reflect normalization/visitors, scene spawn/export, prefab expansion, patches and Editor diagnostics.
Prerequisite
F04 shares the value model; F06 supplies resolution across incarnations. Close scalar inconsistencies without waiting for every recursive feature.
Acceptance
Explicit/default, required/optional and local/external/missing cases agree across entry points. Unloaded durable references remain distinct from invalid local references.

F06 · Permanent claims couple durable identity to one runtime incarnation

P1Structural contract riskProposedIntentional current contract
Evidence
Accepted ADR 0058 requires permanent claims. domain.rs:1011 rejects claimed references; :1611 retirement does not reclaim them. Default capacity near one million measures world history.
Counterexample
An NPC unloads and returns with the same durable UUID in one world; rebinding is rejected. Assigning a new durable UUID breaks saved references.
Direction
Revise the ADR first. Separate durable identity, active binding/runtime incarnation and stale-token rejection. Never make old runtime tokens silently resolve to a replacement.
Migration
Identity domain/references, scene replacement and retirement, command targets, export/serialization, diagnostics, later streaming/save.
Prerequisite
F05 unloaded/deleted semantics; precedes broad F07 lifecycle or streaming/save consumers.
Acceptance
Unload/reload preserves durable references but rejects old runtime tokens; cross-world and duplicate active bindings fail; residency cycles do not exhaust history-sized claims; deletion/exhaustion stay explicit.

F07 · Native reconciliation is proved by a fixture, not independent owners

P2Structural contract riskProposedHigh confidence
Evidence
domain_reconciliation.rs:377 manually retires native/required/hook state and synchronizes it. Strict retirement still rejects lifecycle work at spawn.rs:1324 and nara_ecs/__private.rs:155.
Counterexample
Independent physics and audio owners must coordinate unload, pending work, stop and retry. A fixture's hand-coordinated teardown does not prove that reusable workflow.
Direction
Prove both real owners with stop, cleanup, reconcile and degraded/unavailable states. Extract only the coordination they share. No universal native rollback promise.
Migration
Scene/identity retirement, native owners, runtime close, fixtures, Editor stop/restart diagnostics. Keep strict guards until each consumer migrates.
Prerequisite
F06 incarnation semantics and F09 thread ownership where relevant.
Acceptance
Unload/replace/stop releases each native owner once; pending work retains ownership; partial failure remains visible/retryable; stale entities cannot reactivate accidentally.

F08 · Custom schedules have configuration but no managed execution path

P2Structural contract riskProposedIntentional current behavior
Evidence
App lib.rs:1244 / :1281 accept arbitrary labels; runtime.rs:2812 keeps registry outside World. Private driver :1832 runs fixed stages. schedule_registry.rs:25 deliberately asserts custom schedules are inert.
Counterexample
An extensible physics substep needs N executions per tick. World scheduling cannot reach this same registry; a second registry/private Schedule or App change is needed. Ordinary FixedUpdate SystemSets remain usable.
Direction
Add a configuration-time declared managed sub-schedule driver with the real consumer. Preserve fault/time/safe-point ownership; avoid unrestricted host execution.
Migration
App registry/driver, tests and domain substep composition. Existing CoreStage and GameplayCommandSet consumers can remain.
Prerequisite
F09 thread ownership; a real repeated/independent-clock consumer, not architectural completeness alone.
Acceptance
External plugins extend the same schedule; pause, exact step, commands, errors and configuration freeze have explicit behavior.

F09 · Runtime mobility is weaker than NonSend and retirement assumptions

P2Structural contract riskProposedSend trait confirmed
Evidence
RuntimeInstance :2222 / owner :2812 have no thread marker. Metadata probe confirms RuntimeInstance: Send. Raw configuration admits NonSend data; :3289 quarantine is thread-local and :1243 requires owner-thread draining. :925 mutable close access is Resource-only.
Counterexample
A thread-affine audio controller is inserted, then the admitted runtime moves for drive/drop. Access panic and wrong-thread forgetting are inferred from the substrate; no cross-thread NonSend SDK scenario was executed.
Direction
Keep data-only recipes transportable. Explicitly bind App/sealed/admitted states capable of retaining NonSend values to their owner thread, including before admission and through retirement. Add bounded NonSend close polling if needed. No universal cross-thread executor.
Migration
Admission/runtime/retirement types, project_host holders, native shutdown integration and compile-time ownership tests.
Prerequisite
Settle intended mobility using the confirmed auto-trait; before thread-affine domains and F08.
Acceptance
Compile-time mobility covers configuration and execution, including configured NonSend values before admission; wrong-thread effects are prevented/rejected; close and destruction preserve the owner thread. Independent runtime construction on other threads remains possible.

F10 · Completed transforms do not cover same-tick read-then-write stages

P2Structural contract riskProposedMedium-high confidence
Evidence
hierarchy/lib.rs:181 completes after Simulate, then propagation.rs:126 completes transforms. Public helper lib.rs:75 correctly supports consumers after propagation.
Counterexample
Animation changes a parent; physics needs its current world pose then writes local state. Simulate reads prior completion; ordering Simulate after final propagation cycles; writing afterward requires another completion.
Direction
Prove an owner-provided on-demand current-pose helper. Distinguish current reads from cached completed globals; keep immutable derived components and final propagation.
Migration
Transform helpers, bounded ancestor traversal, physics/animation integration and tests. Existing post-propagation/render readers can remain.
Prerequisite
F08 if substeps are used; real mutation/read semantics. Avoid arbitrary global completion barriers.
Acceptance
Animation-to-physics sees current ancestors; writeback reaches final projection; malformed hierarchy, stale entities and non-finite values fail consistently.

F11 · Each ordinary hierarchy write validates and copies the whole topology

P2Structural contract riskProposedCost established; budget unmeasured
Evidence
writer.rs:310 wraps one operation as a batch; :351 validates/copies all topology; :728 repeats the baseline per batch. Deferred single Commands use it at :332.
Counterexample
Independent audio, attachment and streaming plugins issue small writes. K operations can cost O(KH) for H members. One owner's batch helps, but does not merge independent producers.
Direction
Keep atomic ordered batches; use a trustworthy completed generation and affected-edge/ancestor candidate overlay. Retain full validation at dirty/raw boundaries and for diagnosis.
Migration
Hierarchy writer/validation/completion, scene transactions and Editor hierarchy operations. Preserve Parent/Children ownership and document shape.
Prerequisite
Mutation authority and invalidation must be reliable first. Do not delete validation as a local optimization.
Acceptance
Measure large-world small edits and independent producers; invalid operations remain atomic; raw writes invalidate completion; sibling order and scene/Editor behavior remain correct.

F16 · Custom font ownership does not close shaping through rasterization

P2Structural contract riskProposedHigh confidence
Evidence
UiCompiler::new, compiler.rs:36 accepts FontFace; planner/mod.rs:41 fixes the bundled face. raster.rs:57 rejects FaceMismatch.
Counterexample
UI shapes successfully with a custom face, then the default presentation planner cannot rasterize the glyph runs.
Direction
Share an immutable FontSet owner across shaping, planner, rasterization, atlas identity and retirement. Larger limits do not repair identity.
Migration
Text ownership, UI compiler/planner composition, atlas/cache identity, runtime/Editor presentation. Retain convenient bundled defaults.
Prerequisite
F02 owner fix; a custom-font consumer defines the bounded FontSet surface. No speculative dynamic provider framework.
Acceptance
Custom faces shape and present with one owner; incompatible runs fail before upload; mixed faces, clones, resets, targets and retirement preserve cache identity.

Retain these boundaries

  1. Thin ECS access, domain-owned writes. Keep mature queries, commands, schedules and change detection. Do not build another ECS facade; restrict writes where persistence or native ownership requires it.
  2. Frozen recipe and one managed owner. Plugin extension does not require mutable runtime composition. Keep typed SystemSets and make new execution paths use the same owner.
  3. Persistent documents separated from native effects. Preserve atomic document changes, explicit degraded/unavailable states and strict guards until their consumers migrate. Do not promise arbitrary native rollback.
  4. Semantic Editor operations and explicit channel lifetime. ADR 0036 already distinguishes observations from durable requests. Frame cleanup is not a durable native-cleanup queue; domains own retention across pause and zero ticks.

Watchlist, not immediate redesign

  • Image-specific content/reload routing needs a second asset domain before generic expansion. Live UUID relocation must preserve identity and last-good content; reopening a fresh database is a different operation.
  • Default task pools need a process/host budget when consumers combine. Thread-count formulas alone do not prove overload.
  • Linux directory behavior is a platform-consumer gap, not a reason to replace the filesystem abstraction.
  • Tilemap, save, scene streaming, gamepad, IME and advanced rendering expose these seams. Their absence is not a foundation defect.
