# Engine consumer contract review

The third November 19 review found three high-priority defects. An Undo can lose authored data and mark the document clean, Project Check can reject the schema bundle emitted by its own recipe, and disabling one entity can fault a healthy hierarchy. Eight further engine findings cover authoring, presentation, Cook and asset residency. Two gameplay defects affect the games shipped as examples.

The review started at `f5f0b47` and rechecked the affected paths at `8411487` with concurrent worktree changes present. The earlier reviews track their own repairs. [First workflow review](2026-11-19-engine-workflow-review.md) · [Second workflow review](2026-11-19-engine-workflow-review-follow-up.md)

## P1 findings

### Undo can lose a list element and mark the document clean

In both Scene and Prefab, register three optional native `u64` fields with paths into `slots[0]`, `slots[1]` and `slots[2]`. Start with `[10, 20, 30]`. Submit `ApplyInspectorCommand(RemoveField)` for the middle field through `EditorWorkspace::apply_command`. The document becomes `[10, 30]`. Undo returns success and `dirty=false`, but the document now contains **`[10, 20]`**. Removing the last field instead makes Undo fail with `scene.patch-invalid-field-path`. A named map field in the same component survives the entire cycle. The built-in Inspector suppresses the indexed Reset action. Native tools can submit it through the public workspace. [Inverse patch](../../crates/nara_scene/src/patch.rs#L2834) · [List removal](../../crates/nara_reflect/src/value.rs#L432) · [Index assignment](../../crates/nara_reflect/src/value.rs#L339) · [History state](../../crates/nara_scene/src/authoring.rs#L576) · [Inspector guard](../../editor/src/frontend/controls/owned_inspector.rs#L2298)

`RemoveField` shifts the tail, while its inverse overwrites the element at the old index. For the current Reset contract, reject an indexed leaf at the patch boundary before changing history. If list deletion is supported, its inverse must insert at that index or restore the exact prior container. Test first, middle and last elements in both document kinds. Compare the complete document and the clean marker after Undo, then repeat Redo. Bevy's reflected list exposes distinct operations for insertion and removal. Godot's array Undo retains the old size and properties. [Bevy list operations](https://github.com/bevyengine/bevy/blob/779770720e6ad916c1de38cf66a67d0e079ed1e3/crates/bevy_reflect/src/list.rs#L71) · [Godot Inspector array history](https://github.com/godotengine/godot/blob/b070e63b161aa816afac71dcfc9d60859d38f220/editor/inspector/editor_inspector.cpp#L3294)

### A generated schema bundle can fail Project Check after an ordinary JSON read

Give a selected data owner an optional `F64` field with the finite default `0.9333333373069763`. Resolve its product recipe, serialize the resulting `AuthoringSchemaBundle` directly to `schema/authoring.bundle.json`, then call `check_project` with the same recipe. Check returns `SchemaMismatch` with `project.runtime-agreement.selected-owner-divergent`. A single-owner bundle's fingerprint changed from `3f4a23ca…` to `f82913a4…` on read. Independent Scene **and** Prefab encode/decode/encode tests changed the same literal to `0.9333333373069764`. With `0.5` all three round trips retained their values and Check passed. [Workspace JSON dependency](../../Cargo.toml#L135) · [Bundle reader](../../crates/nara_reflect/src/authoring_bundle.rs#L331) · [Fingerprint input](../../crates/nara_reflect/src/schema.rs#L2139) · [Data-owner agreement](../../src/project_host/runtime_agreement.rs#L174) · [Scene and Prefab reader](../../crates/nara_scene/src/format.rs#L1727)

The persistent formats need to own exact binary64 round trips. Keep the strict owner comparison, which correctly detects the changed value. The isolated module consumer already enables `float_roundtrip` for its replay fixture. That feature recovered the exact bits in a separate parser control using Nara's pinned `serde_json` 1.0.150. Put the guarantee on the engine's serialization dependencies and run the generate → Check and document round trips in an independent consumer feature graph. Godot also exposes an explicit precision choice for JSON publication. [Independent replay manifest](../../tests/fixtures/module-consumer/Cargo.toml#L38) · [Reflect dependency](../../crates/nara_reflect/Cargo.toml#L21) · [Scene dependency](../../crates/nara_scene/Cargo.toml#L22) · [Godot JSON writer](https://github.com/godotengine/godot/blob/b070e63b161aa816afac71dcfc9d60859d38f220/core/io/json.cpp#L98)

### Disabling one entity can fault a valid hierarchy and conceal a broken one

Place `P → C` with `HierarchyWriter`, start a Runtime with `HierarchyPlugin`, then render one frame. In the next Update, insert Bevy's `Disabled` on one endpoint and place an unrelated root. Direct ECS reads still find `C.Parent == P` and `P.Children == [C]`. With the child disabled, `validate_hierarchy` returns `ReverseUnexpected`. With the parent disabled, it returns `ReverseMissing`. Both calls to `drive` fault with `System` before the second Render. Adding the root alone renders both frames. Disabling the child alone makes direct validation fail immediately; the managed fault waits for a topology change that triggers validation. [Parent and child scans](../../crates/nara_hierarchy/src/validation.rs#L126) · [Membership scan](../../crates/nara_hierarchy/src/validation.rs#L239) · [Managed publication](../../crates/nara_hierarchy/src/lib.rs#L346)

The reverse control exposes a second consequence of the same filter. Disable both entities and remove `C.Parent` while leaving `P.Children` intact. Validation returns `Ok(())` and Render runs. Structural validation needs to enumerate all placed entities independently of the gameplay query filters, including custom disabling markers. Keep both valid-edge and broken-edge controls in the managed Runtime suite. Bevy documents that disabled entities still exist and remain directly accessible in the World. [Hierarchy invariant](../architecture/adr/0100-runtime-structural-hierarchy-and-completed-2d-transform-projection.md#L223) · [Bevy disabling semantics](https://github.com/bevyengine/bevy/blob/779770720e6ad916c1de38cf66a67d0e079ed1e3/crates/bevy_ecs/src/entity_disabling.rs#L39)

## P2 Cook and residency findings

### Cook loses integer types when canonicalizing domain settings

A custom importer accepted a `u128` sidecar seed. Source loading delivered exactly `18446744073709551616` (`2^64`) and the public `check_project` succeeded. `build_source` then returned a domain error and `prepare_project_cooked_content` failed. The adjacent `2^64−1` control passed Check, produced `Built`, then `Hit`, then a successful Cook with the retained group. Runtime acquisition returned the original integer. [Project Check](../../src/project_workflow/check.rs#L249) · [Typed metadata admission](../../crates/nara_asset/src/format.rs#L137) · [Normalized input for the build](../../src/asset_build/execute.rs#L634) · [Settings conversion](../../src/asset_build/execute.rs#L829) · [Cook consumer](../../src/project_tooling/project_cook/content.rs#L187)

Sorting object keys currently reparses the normalized settings into `serde_json::Value`. That step changes the integer token to `1.8446744073709552e+19`, which the typed importer cannot read as `u128`. The `float_roundtrip` control fixed binary64 precision but left this failure intact. A parser built with both `float_roundtrip` and `arbitrary_precision` retained the integer token. Preserve the typed importer's complete numeric domain during canonicalization, keep deterministic object ordering, and exercise fresh builds, cache hits and retained groups at the integer boundary. [Accepted typed build contract](../architecture/adr/0103-concrete-domain-owned-asset-import-execution.md#L278)

### Renaming a source with a stable UUID blocks Scene replacement and re-entry

Keep a Scene's `AssetRef::Product` and the asset UUID unchanged. Change `palette.png` to `colors.png` and update its sidecar path. A public `ProjectScenes` rescan reached `Ready`. Calling `commit_prepared_project_scene` reported `project.scene.asset-identity-conflict` and the request became `Rejected(CommitRejected)`. The old Scene instance, gameplay, pixels and asset versions were preserved, with zero new asset events. Leaving for an empty Scene successfully removed the typed asset and catalog record. Returning to the original Scene **still failed**. A fresh headless World loaded the same renamed project and committed a rescan. The source Scene bytes and prepared content stamp matched across the hot and cold tests. Repeating the experiment with a Material rename produced the same outcomes. [Rescan](../../src/project_host/runtime/scene_requests/api.rs#L280) · [Explicit commit](../../src/project_host/runtime/scene_requests/api.rs#L646) · [Catalog replacement](../../src/project_host/runtime/content_residency/catalog.rs#L36)

After the last user leaves, `AssetServer` still binds the handle to the old path. In isolation, reserving the renamed record returns `AssetIdAlreadyBoundToPath`. Accepted ADRs 0007 and 0117 preserve Product identity across a source rename and reject simultaneous UUID claims at different locations. Give the replacement transaction authority to transfer a verified old binding to the new location, including when the typed asset has already retired. Preserve the Product handle and cover rescan, leave/return and an actual second live claimant. [Image reservation](../../src/project_host/runtime/content_residency/images.rs#L225) · [Material reservation](../../src/project_host/runtime/content_residency/materials.rs#L337) · [Path refusal](../../crates/nara_asset/src/server.rs#L412) · [Location and identity](../architecture/adr/0007-asset-identity-and-import-pipeline.md#L85) · [Source rename](../architecture/adr/0117-2d-foundation-ownership-and-authoring-contracts.md#L248)

### TileSet sharing and retirement disagree about the same replacement

Publish a TileSet against a 1×1 Image, change the tint red channel from `+0.0` to `-0.0`, then ask the existing owner to share it. The share returns `Superseded`. Replacing it publishes version 2 with bits `0x80000000`. Retiring with the **version 1 receipt** then removes version 2 from `Assets<TileSet>`. Changing the channel to `0.25` also rejects sharing, but the old receipt now fails and version 2 stays resident. [Scene publication modes](../../src/project_host/runtime/content_residency/tilesets.rs#L53) · [Sharing comparison](../../crates/nara_tilemap/src/content/publication.rs#L303) · [Claim reuse](../../crates/nara_tilemap/src/content/publication.rs#L335) · [Retirement](../../crates/nara_tilemap/src/content/publication.rs#L517)

Sharing compares float bits. Replacement reuses its retirement claim on ordinary `PartialEq`. Use one declaration-equivalence rule for both decisions. The existing exact comparison is the smaller change. If signed zeros should represent one declaration, canonicalize them on admission and apply that rule consistently. Test that every replacement classified as different revokes the previous receipt. [Existing comparison](../../crates/nara_tilemap/src/content/publication.rs#L629)

## Verification and repair order

Start with exact Undo, the engine-owned JSON feature set and hierarchy validation. Each has a public consumer that reports success for lost state, rejects its own persisted output or stops a running game. The numeric Cook failure needs its own integer-token test even if it ships with the binary64 fix. The Game View and picking fixes can proceed independently.

On Windows x64, the review ran the new cases through public CPU or headless paths using Rust 1.95.0, compiled probes and dependencies from the shared build. The Editor history checks exercised workspace commands. Inspector reopen used JSON and the authoring session. Game View used the actual fixed-step Runtime. UI checked draw items, hit testing, keyboard focus and the published semantic snapshot. Picking activated a CPU presentation receipt. The gameplay probes used source projects copied to temporary directories. Native window interaction, GPU pixels, physical filesystem notifications and other operating systems were outside this run.

Fourteen existing regression tests also passed when run individually from the shared Windows release test binaries. They covered shutdown fault delivery, structural Undo, spent task handles, text raster placement, historical focus, semantic ancestry, Gilrs focus continuity, mouse-release provenance, Inspector sibling edits, Prefab navigation identity, Step with all cameras clipped, typed Cook group admission, dependency-free Scene Cook and two-profile Export delivery. The Export control exercised a concurrent worktree change. This verification used existing test binaries and focused probes.
