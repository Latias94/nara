# Nara engine workflow review

Reviewed on Windows x64 on November 19, 2026. The working tree was on `refactor/foundation` at `06052744a591`. The local reference checkouts were Bevy `779770720e6a` and Godot `b070e63b161a`. Five parallel source reviews covered scenes and persistence, assets and delivery, rendering, UI, and spatial/physics consumers. Integration probes also covered App, Input, and the boundaries between those areas. The review follows the Rust-first desktop game workflow in the [strategy](../../STRATEGY.md).

The first two repairs should protect authored work. An ordinary Save can publish edits under a different stable ID, and an entity deletion can produce a document the editor accepts but the scene compiler cannot resolve. The next four affect whether a valid game keeps running, loads its images, or can be packaged. Each has a small regression case that can be kept at its owning boundary.

## High priority

### 1. Save can write edits made to stable document A into document B

**Reproduced through the public Editor session and filesystem.** Open a Scene in a `stable_metadata` project, add an entity, and change only the UUID in its `.meta` to another valid value before requesting Save. The result was `Saved`, the document became clean, and the added entity appeared in the on-disk body now belonging to B. There was no concurrent write during Save. Scene and Prefab use the same background publication pattern. Reopen already checks the admitted source key again. [Save dispatch](../../src/project_host/runtime/editor/persistence/background.rs#L63) · [body identity and digest checks](../../src/project_host/file_publication.rs#L642) · [saved-state acknowledgement](../../src/project_host/runtime/editor/persistence.rs#L1168) · [Reopen comparison](../../src/project_host/runtime/editor/source_admission.rs#L36)

Carry the opened document's identity into file publication and revalidate its sidecar before replacing the body. On a prepublication mismatch, preserve the draft, Undo history, and original bytes. If the pair changes in the publication window, surface the existing uncertain outcome. A lower-cost first fix fits the current two-file format. Storing the stable ID in the document envelope is a larger format decision that would let identity and body travel in the same write, as they do in Godot text scenes. Test both Scene and Prefab, including a change while the worker is waiting. [Existing gated Reopen test](../../src/project_host/runtime/editor/persistence/tests.rs#L605) · [ADR 0038](../architecture/adr/0038-scene-prefab-authoring-identity-and-provenance.md#L283) · [Godot text scene writer](https://github.com/godotengine/godot/blob/b070e63b161aa816afac71dcfc9d60859d38f220/scene/resources/resource_format_text.cpp#L1997)

### 2. Two equivalent local references give opposite results on entity deletion

**Reproduced through Scene authoring and JSON readmission.** A known, required reference field on A points to B. With `SceneLocal(B)`, deleting B was refused, both entities remained, and the revision stayed at 0. Changing only the representation to `AuthoredEntityReference::source(B)` made the same deletion succeed, advanced the revision to 1, and left a one-entity document that encoded and reopened successfully in authoring. The zero-hop authored reference still names B. The compiler looks up the target and cannot resolve it. [Reproduction fixture](../../crates/nara_scene/tests/structural_authoring.rs#L280) · [zero-hop constructor](../../crates/nara_identity/src/reference.rs#L170) · [authoring validation](../../crates/nara_scene/src/validation.rs#L1029) · [budgeted reclassification](../../crates/nara_scene/src/authoring_decode/reclassification.rs#L581) · [compiler target lookup](../../crates/nara_scene/src/prefab/overlay/compile/staged/inputs.rs#L174)

Give the reference domain one operation that identifies a directly addressed source-local target in either representation. Use it in Scene/Prefab removal and reclassification, including explicit fields and contextual defaults. Keep lexical Prefab paths and genuinely external references subject to their existing scope rules. The regression should compare final document, revision, and Undo state for both encodings. [Deletion contract](../architecture/adr/0090-unavailable-schema-and-lossless-authoring.md#L162) · [Godot editor target resolution](https://github.com/godotengine/godot/blob/b070e63b161aa816afac71dcfc9d60859d38f220/editor/docks/scene_tree_dock.cpp#L2108)

### 3. One deferred key can exhaust input during an otherwise idle managed pause

**Reproduced with current Input source.** With a 24-event limit and one maintenance frame per move, a paused Runtime accepted 64 pointer moves and retained zero records. After one key press during the same pause, it accepted only 17 moves. Move 18 returned `CapacityExceeded { limit: 24, retained: 18, requested: 7 }`. Observation, UI, and action scanning had all reached sequence 18. Only sequence 1 had a deferred action. Resume freed all 18 records. The stock Winit path escalates a refused cursor move to runner failure and starts shutdown. The probe exercised the Runtime refusal, and source tracing established the desktop consequence. [Deferred action staging](../../crates/nara_input/src/timeline/owner.rs#L1837) · [prefix-only reclamation](../../crates/nara_input/src/timeline/owner.rs#L1896) · [cursor ingress](../../crates/nara_winit/src/lib.rs#L1699) · [driver error](../../crates/nara_winit/src/lib.rs#L2414) · [shutdown](../../crates/nara_winit/src/lib.rs#L1943)

Reclaim individually completed records after their frame copies expire, preserving the sequence order of live records and the reserved release/retirement capacity. Raising the cap only delays failure. The existing paused test fills the queue with genuinely deferred key edges. Add the mixed key/motion case and prove that the original key still resolves exactly once after Resume. Godot's accumulated motion illustrates how short pointer-event lifetimes can be, while Nara still needs its own exact press and release semantics. [Existing paused test](../../crates/nara_input/src/projection_tests.rs#L414) · [Input retention contract](../architecture/adr/0041-input-routing-actions-text-focus-and-accessibility.md#L177) · [Godot input buffer](https://github.com/godotengine/godot/blob/b070e63b161aa816afac71dcfc9d60859d38f220/core/input/input.cpp#L1655)

### 4. Resizing a valid split-screen window can fault the desktop Runtime

**Reproduced through camera extraction and packet construction.** With the existing two 640×720 viewports and no fixed WorldCanvas, packets at window widths 1280, 960, 1280 returned `Ok(Some(2))`, `Err(ViewportOutsideTarget)`, `Ok(Some(2))` respectively. The explicit right viewport survives extraction with its old width. In the stock WGPU Host, that middle result is promoted to a sticky `RuntimeFaultKind::System`. The last CPU result demonstrates that the camera data becomes usable again if the Host has kept the game alive. Derive the effective viewport from the authored rectangle and the current window extent during extraction. Use it for projection, picking, and clear order. Skip a view when its intersection is empty and preserve the authored rectangle for subsequent growth. Keep strict validation for invalid caller-built packets. The integration regression is a window shrinking and growing with both cameras still active. Bevy handles the target-size change before updating the camera projection. ### 8. A TileSet can keep old atlas pixels indefinitely after a transient budget refusal

**Reproduced through the real Sprite/TileSet schedules.** Two 2×1 RGBA8 generations fit the 16-byte budget. Without retaining any external packets, publish pixel values 10, 20, and 25 in successive frames. A standalone sprite showed `10 → 20 → 25`. A tile using the same atlas showed `10 → 20 → 20` and still showed 20 on frame 6, when only 8 bytes were retained. Swapping extraction vectors leaves the retired image in scratch until the next Extract. TileSet reconciliation runs earlier in TaskUpdate, records the third dependency observation before the reservation succeeds, and skips that observation on later frames. [Extraction swap](../../crates/nara_sprite_render/src/types.rs#L130) · [next-frame clear](../../crates/nara_sprite_render/src/extract.rs#L55) · [retention budget](../../crates/nara_tilemap/src/content.rs#L738) · [retry suppression](../../crates/nara_tilemap/src/content.rs#L817) · [integration fixture](../../crates/nara_sprite_render/tests/tileset_content.rs#L308)

Release old elements immediately after the successful swap so scratch retains only vector capacity. This addresses the reproduced case within the current contract. For recovery after a genuine external packet pins the old image, ADR 0117 currently suppresses repeated failures for an unchanged dependency observation. A broader change would make available capacity part of the retry condition. Test that an external packet keeps its original pixels and that releasing it allows the desired generation to appear under that policy. [Retention contract](../architecture/adr/0117-2d-foundation-ownership-and-authoring-contracts.md#L293) · [Bevy extracted asset drain](https://github.com/bevyengine/bevy/blob/779770720e6ad916c1de38cf66a67d0e079ed1e3/crates/bevy_render/src/render_asset.rs#L448)

## Refactor order

1. **Protect source identity and references.** Start with the A/B Save case and the two encodings of the same local reference. They can be fixed independently and verified on temporary projects. A later identity-envelope migration can use these cases as its acceptance tests.
2. **Fix input lifetime and visible geometry.** Reclaim completed input individually. Keep authored bounds, full layout bounds, visible bounds, and the coordinates used by a particular presented frame explicit. Apply that rule in each existing camera, Canvas, UI and pointer owner. Retain ordering and held-release guarantees while shrinking the 91 MiB default reservation.
3. **Make accepted asset work finish or become retryable.** Preserve which file changed, distinguish invalid content from temporary capacity pressure, and resolve product identities explicitly at the Cook boundary. Use a normal sprite and a tile referencing the same image as the first cross-module reload test.
4. **Close partial-operation and sample gaps.** Check unload prerequisites before the first entity is retired, capture coherent fixed-time state, and migrate the sample's pickup calculation to the existing fixed spatial snapshot. These can land as small independent changes. The Vulkan status path warrants a separate backend experiment.

The migration with the widest reach is input storage. A compact event record must still outlive a paused consumer, retain the mapping in force when the event was staged, and deliver its terminal edge once. Establish those observations at the public API before changing storage. The geometry fixes have lower migration cost. Existing authored viewports, full primitive rectangles, and window extents already contain the information needed to calculate per-frame results. The first two authoring fixes can also ship with the current file formats.
