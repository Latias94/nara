## P2 · The property directory cannot expand the 128th Map in a record

Use a record with 130 Map members, each containing the short keys `a` and `z`. The directory lists all 130 members. Expanding one row under member 127 consumes 255 scan entries. Expanding member 128 exhausts the maximum 256-entry allowance for every legal page size from 1 through 256. A point read of its `a` costs 129 entries, and a value page returns both keys for 130 entries. Live and prepared views of both Scene and Prefab gave the same results.

The directory first resolves the parent Schema path and then walks it again to locate the Map value. Each pass examines all 128 preceding-or-selected member declarations. Retain the resolved location for the value lookup and continue charging the real child scan. This double scan also exists in the parent of the long-key pagination fix. ## P2 · A running Server can exhaust its startup deadline waiting to configure a checkpoint

Select a 20 s fixed timestep, `time_scale = 0.25` and a 60 s frame clamp. A running Server with a writable fresh `--save` slot exited 1 after 60.07 s at tick 0, before Ready. The identical pack without a slot started and closed in 0.08 s. With `--paused --save`, it configured the slot at tick 1 and closed in 0.08 s. The ordinary 20 ms running profile with a slot also passed.

The running startup queues slot configuration for tick 1 and withholds the control reader until that tick executes. This profile earns its first tick after 80 real seconds, beyond the fixed 60 s deadline. Four explicit advances of 20 real seconds on the same pack accrued 5, 10, 15 and 20 virtual seconds and delivered a marker once. Perform the existing exact initialization step for a running launch and establish the live clock afterward, or configure the slot directly during startup. Preserve ordinary pacing after Ready. Bevy's startup schedules are an example of initialization with a distinct lifetime from the fixed loop. ## P2 · The vendored macOS scancode table merges two physical positions

Both `0x32` and `0x0a` map to `Backquote`. With a valid backquote action, press the first code, press the second, then release the second while the first is still held. The second press is deduplicated and the release ends the action early. In source and processed runs, movement stopped at X = −9.6. Using a semicolon as the second key kept the first action held through X = −19.2. Godot assigns two distinct key identities to these codes. Bevy's ingress likewise relies on the physical code supplied by Winit.

Preserve distinct positions in the platform conversion and exercise overlapping holds on a Mac ISO keyboard. The test executed the vendored macOS mapping function and Nara's input pipeline on Windows. Native macOS event delivery remains unverified. ## Architecture and verification scope

The tests support keeping the two-file Prefab Apply protocol. Replacing either file with byte-identical content under a new file identity invalidated the pending operation. A dirty destination that already held the desired value still needed its exact saved revision. After closing and recreating the Editor application between the two saves, a fresh inspection could finish the edit. A whole-document compile showed two instances inheriting their own local child endpoints and a third retaining its override. Selected-instance verification covers the selected instance. In a separate case, a sibling explicitly suppressed the newly referenced child and full composition diagnosed that sibling after both saves. [Apply workflow](../../src/project_host/runtime/editor/prefab_inspection/apply.rs) · [Apply qualification](../architecture/authoring-read-projection-design.md#L724)

Keep platform key normalization and semantic actions in the first-party Input module, desktop configuration checks in the project workflow, and movement semantics in the game. Windows punctuation now works through all three layers. For delivery, the admitted Scene already supplies entity identities and membership. Let the runtime and the verifier read those facts from the same place. For Editor mutations, preserve the identity of the observed parent along with the requested declaration.

Verification ran on Windows x64 with Rust 1.95.0. The independent consumers used registered panels, real file saves, reopened packs, native Windows event tests and released command-line binaries. Targeted probes also compiled current game entry points and Cook preparation with matching cached libraries and pack-specific bootstraps. The expanded tick-budget control changed only a temporary verifier. The component writer and related inputs were rechecked against `7871fd1`. Inspector feedback was exercised at its production command and draft handler. The macOS check covers the mapping function. This was a focused review with selective builds and tests.
