# Verification

Verified corrective commit `76bfc6c` against the strict Export part of SGE-U4. The correction
closes a late review finding: selecting a Cargo executable and checking one nominal project closure
was insufficient when that executable's actual provider-capable product composition admitted a
different source member set or runtime-directory layout.

# Result

Export now runs both selected release executables through their normal startup path before any
publication transaction is created. Each product reports its exact executable, manifest, runtime
content, authoring bundle, schema composition, and ordered startup-closure plan facts. The build
receipt accepts those observations only when the complete closure plan equals the checked closure
that Export will stage. The closure-plan digest length-frames every ordered runtime directory and
every member kind, path, length, and digest, so a profile-specific empty directory or additional
source member cannot be hidden by the Runtime content digest.

Published arbitrary-CWD acceptance remains a second, separate proof of the final exported layout.
The pre-publication observation is cooperative product evidence, not an anti-tamper claim against
malicious project code.
