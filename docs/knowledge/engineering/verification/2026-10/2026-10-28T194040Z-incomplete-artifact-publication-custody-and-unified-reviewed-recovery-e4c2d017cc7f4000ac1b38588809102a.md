# Result

`EditorSourceToolIncompletePublication` comes only from actual destination publication. It retains
the original project/store/destination, nonzero correlation ID, directory receipt, intended manifest
and actual created subset. Each member records its actual path/role/baseline, separate optional sync
fact, reader and cleanup-only custody. A failed receipt replace retains its actual temporary name,
never a fictitious ready receipt or a competitor's file. Pre-publication directory failure retains
a separate orphan; its now-unused member/cleanup fields and methods are removed.

Cleanup-to-reader handover strictly reopens the original path while the original handle remains
live, compares actual objects, retains the reader, and only then closes duplicate cleanup. No
discard or unlink happens in preparation. `TemporaryFileCleanup::same_object` is a read-only
live-handle query, including independent Host sessions; invalid/unproven objects remain errors.
Directory creation DELETE handles are handed over only after all member cleanup parents release.
Failure returns original publication plus remaining custody; successful earlier handovers retain
their readers rather than pretending no progress occurred.

The canonical format remains 1 with one reader. `EditorSourceToolArtifact` replaces the old
installation-shaped inventory entry: ID/package/directory/manifest plus Ready receipt or Incomplete,
and actual members. Required root arrays are `artifacts` and `reclamations`; recovery targets an
artifact ID. Ready retains complete metadata/tool constraints. Incomplete admits actual subsets or
zero members and at most one bounded root receipt temporary. Previous shapes and unknown authority
fields reject. Bounds remain 32 artifacts/records, 66 members and 2 MiB. The ready installed graph
keeps its original exact receipt/requirement model and execution admission.

Session/Application prepare incomplete registration without writes. Prepare refusal returns the
publication; confirmation refusal returns the prepared candidate. Callers can recover unique
incomplete custody and explicitly reprepare. After asynchronous registration failure, the Session
retains actual custody independently of disk observation; explicit reconcile plus retained-object
registration preparation retries only that existing owner. An ID read after fresh Open cannot
reconstruct it. All mutations reuse existing Tasks and file publication.

Both Ready and Incomplete use the existing original-basis disposal review, actual graph/source/user
checks, namespace leases, pre-unlink intent, exact-object unlink receipts and partial/cancelled
results. Unknown siblings, competing ready receipts and project-owned copies remain unselected.
Fresh Open observes facts without automatic deletion or execution. Native template remapping and
the rest of the foundation Goal remain separate.
