# Result

Mixed preparation reuses one preflight loop and the existing unbound/bound publication owners.
All native/data retained effective values share residual node/byte admission. Reflect owns the
existing default plan; its internal aggregate entry accepts true zero residual ceilings, checks
raw depth and complete default/key cost before cloning, and returns exact logical cost.
Current-version values stay borrowed until admission. Trusted native migration/codec internals
retain ordinary allocation semantics; this is not a total heap/RSS bound.

Scene prepares complete owner-local data groups before target allocation, then stages one
move-only carrier per entity in the existing insertion plan. Persistent receipt declaration still
sees empty targets. Carrier insertion and native apply share the final exclusive tail. Carriers
retain only records and owner-local data snapshots, plus transient World/entity custody; they
retain no complete native registry, VM or executable lease. Product writes and native codecs
cannot claim the carrier type. Late hooks/observers/required components refuse without a whitelist.

`SceneComponentBindingsPlugin` freezes the actual managed native/data selection. Its private
identity/revision guards detect replacement, including transient remove/reinsert. App now
composes guards in deterministic installation order, rejects duplicate plugin IDs and preserves
canonical sticky faults. Ordinary and advanced managed replacement require the exact native
definition; the independently selected projection exception remains. Unbound preflight derives
its selection from the captured definition, not a second caller-supplied binding parameter.

Guarded enumeration/read/set/remove distinguish absence from unavailable/invalid membership,
preserve siblings and reject retired incarnations. A real Startup/Update Rust consumer reads and
writes those records while preserving its immutable source. Error-only asset traversal payloads
are boxed to avoid inflating every successful read result.

Export checks actual native persistent membership and native Rust type coverage across all live
entities before invoking any encoder; frozen empty/subset/same-ID-different-type definitions
refuse. Managed native and mixed export validate exact applicable authority. Both families lower
Schema-declared assets after effective defaults using explicit immutable metadata and share the
same entity/persistent remap and aggregate output allowance. Native-only metadata export has an
explicit public entry. No encountered data member is silently omitted.

The independent fixture uses only public APIs and actual JSON/RON files: two data owners plus
native Name, Attach/Edit/Undo/Redo/Save/Reopen, repeated Prefabs, runtime set/remove, stale targets,
live population changes, export/reopen/replay and exact retirement. It does not promote the
private preview/post-commit language experiment.

# Follow-up

Continue the full active foundation Goal. Next integrate the same selected data-owner snapshots
through `ProductRecipe`/`SchemaValidationInput`/RuntimePlan, actual content capture/Check, startup
and native-retirement replacement. Do not treat Authoring bundle availability as executable owner
admission. Then select and integrate one concrete optional language owner, including required
module readiness and physical code custody. Only after the complete replacement remove the
private preview/post-commit storage/export helper.

Ptolemy's next-seam audit (`01a17d71-cebe-74b3-8351-2994de43b18d`) identified this dependency order:
`SchemaContribution`/`ProductRecipeEntry` retain admitted data-owner snapshots; the one recipe
installs a combined Scene plugin and `SchemaValidationInput` retains the one mixed selection.
Content loading must replace both native-only canonicalization and final validation, not merely
switch the lazy compiler call. `ProjectContentSnapshot` should retain native weak witness plus
metadata-only owner witnesses, rather than a strong mixed snapshot pinning executable codecs.
`PreparedRuntimeSchemaAgreement`, `RuntimeStartStamp`, Host World verification and scene-request
admission must compare the whole selection. Only then switch startup/direct replacement/content
residency and the chosen language consumer. Semantic fingerprints must include data owners;
native executable fingerprints keep their separate meaning. Root needs a concrete exact-selection
comparison API; it must not compare hashes or re-admit snapshots during replay.

The closed data family does not implement owner catalog migration, dependency cohorts, Stop-first,
in-flight language replacement or arbitrary escaped-object unload. ADR 0120 remains Proposed for
those obligations. The initial data API uses carrier-level scheduling/change granularity and
default read allowance; a named consumer can require finer access or custom read policies.
Advanced mixed native claims still use the default value allowance. No extra generic SPI was
introduced for those unproven combinations.

Custom-drawn Editor UI remains the destination, not embedding a reference toolkit. Keep its
layout/input/IME/accessibility implementation independent from this storage step. The plan audit
also records staged-custody/asset-reservation/live-export naming, unused reflection storage and
renamed-dependency observer ergonomics as bounded follow-ups. The completed Prefab overlay
comparison is no longer presented as R5's next action.
