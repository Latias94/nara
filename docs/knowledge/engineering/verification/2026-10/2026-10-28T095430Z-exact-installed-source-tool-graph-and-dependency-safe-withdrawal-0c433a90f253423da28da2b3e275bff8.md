# Result

The same `.nara/source-tools/selection.json` authority now holds a bounded complete installed set,
explicit required-installation bindings and an optional desired slot. Canonical format remains
1; the obsolete single-member reader is removed. Members and bindings canonicalize by installation
ID and package respectively. Same release bytes do not choose an installation. Exact registration
is additive, including order-independent repeats; rebind, duplicate/overlapping paths, cycles,
missing/extra declarations and mismatched package/manifest reject. Fixed selection-parent
ancestors cannot be installation roots. Disabled/nonselected members retain their dependencies.

Source capture shares one private byte-work allowance across actual receipts, manifests and
payloads. Charging precedes file opening/allocation and is not refunded on read failure or dropped
capture. Public single-release APIs delegate to the same validator and preserve their old maximum
payload/manifest/receipt sizes. Graph operations use a 128 MiB capture allowance, 32 members,
128 aggregate edges, 16 outgoing requirements and a 64 KiB record. These model captured byte work,
not RSS, arbitrary native allocations or filesystem deadlines.

Project Session owns code-free registration preparation, original-basis confirmation and the
existing finite Tasks/file publication path. Required managed enable consumes actual complete
graph/installation observations; standalone approval still rejects unresolved relationships.
Every invocation rechecks required installations in its worker while the selected executable
uses its approved captured images. Relations grant neither automatic execution nor shared assembly
search paths. No graph solver, proposal interpreter, document store or second process owner exists.

Withdrawal reviews the full reverse closure, including disabled tools. Dropped review changes
nothing; graph/route changes stale it. Confirmation stops affected route/review before publishing
the complete graph successor. Failed publication never restarts that route. Actual child/pipe
return remains independent of Withdrawn; Close retains physical obligations. Reconciliation
admits data without execution and fences new tool work while allowing Disable/source editing/Close.
Source values, prepared-edit ownership, history and admitted metadata retain their owners.

Independent review found and corrected five P2 boundaries: session-only approved installation
routes bypassing graph withdrawal; installation roots containing selection metadata; a new route
bypassing in-flight reconcile; unreadable implicated directories blocking graph withdrawal; and
positive native association being lost after namespace replacement. Executable provenance remains
separate from durable desired-origin data. Read-only withdrawal preparation compares held native
objects only for implicated candidates and conservatively stops an unreadable implicated route;
unrelated or proven different external objects stay outside that set. Background Observe retains
positive links into the same original active token. Later equal receipt bytes at a replacement
path cannot erase that relation. A stale Observe cannot mutate a successor route.
