## Physical Process And Platform Scope

The independent producer reads actual source action-map bytes, consumes the admitted definition
into `ActionMapAsset`, encodes Runtime content and cooks source Scenes. It closes source handles,
checks its owned temporary paths, removes the entire source project, and copies the prebuilt
`processed_input_player` beside a finite processed payload. The child uses an absolute relocated
executable and working directory, `env_clear`, an unavailable PATH, normal Windows system-library
variables, and independently supplied digest/target/profile facts. Cargo builds the fixed binary
before test execution; neither the executing parent test nor the child invokes Cargo.

The positive child verifies no source database/importer resources, actual key/mouse route and
press provenance, semantic-to-command gameplay effects, one context cancellation per action,
fresh-press restoration, rejected malformed later Scene and A-to-B-to-A with unchanged global
bindings/context/held state. Six negative children reject missing or malformed Input, wrong
complete identity, explicit empty code-map conflict, wrong independent digest and wrong expected
target before Startup. The parent checks exact output/payload and reaps each child with a watchdog.

This proves the source-free Windows run path, not an OS filesystem sandbox, arbitrary targets,
cross-build/stripping, a product cook/export command or a full packaged Player. Normalized driver
injection is not physical OS keyboard delivery. The separately executed hidden-window native
tests cover the existing three critical Windows/DX12 Editor input/cadence/view/recovery/retirement
trajectories, not monitor scanout or Linux/macOS execution.
