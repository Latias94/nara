# Details

## Owning model

- Core keeps one physical source table and one actual source/output allocation per member.
  Separate finite environments retain membership, before/after Prefab bindings, asset databases
  and scopes. The selected environment determines the cut; every member Scene is proved in each
  participating interpretation. Cross-profile aliases do not become canonical identity.
- `SourceUpgradeInventory` retains each resolved default/named configuration, actual participant
  membership and metadata visibility. Native-only open Scripts membership grants no catalogue
  visibility. Its global identity database is moved into `identity_catalogue`, separately from
  configuration-local catalogues. `authored_path` retains the actual admitted sidecar spelling.
- The new Project `prefab_extraction` owner consumes actual complete Workspace captures, all
  persistence Host observations, the original source Work and one Host allowance. It captures
  one all-profile inventory, retains separate decoded disk data, shares actual open working Arcs,
  constructs environment bindings through the catalogue owner, proves actual Q/sidecar absence
  under retained ancestors and binds the original Workspace to prepared source correspondence.
  Refusal returns the request and spent counters; no file or live Session changes.
- Q keeps fixed metadata/encoding and remains unopened. Its global UUID/path/case admission uses
  the inventory's already-admitted Asset database, including records visible only in another
  configuration. Final source/saved/publication authority is not inferred from capture.
