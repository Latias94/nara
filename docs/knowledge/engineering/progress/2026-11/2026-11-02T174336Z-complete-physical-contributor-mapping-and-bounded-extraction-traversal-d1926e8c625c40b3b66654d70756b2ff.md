## Physical Ownership And Contexts

`PhysicalDeclarationMap` binds original records and stored instance-path suffixes to actual P/Q
outputs, including dormant declarations and explicit None slots. The old root's components and
instance declaration move to Q while the P anchor's new Q declaration is separately generated.
Original and generated placement claims are disjoint and cover actual outputs; slot-variant
equality alone previously allowed two Last declarations to claim one output.

A real counterexample disproved physical-owner-only independence: a Scene installs P into U:x
through an outer claim while U's unavailable component refers through x into P. U has no physical
P declaration, yet its reference environment changes. The old implementation accepted it; the
red control logged `actual refusal: None`. The private footprint now records both the physical
declaration owner and the modified canonical context. An outer U:x installation creates U-to-P
dependency as well as the physical owner's edge. Dormant additions/claims participate. Incomplete
associations remain Unproven, and reverse closure is queue-based, with each edge visited at most
twice for Affected/Unproven propagation. Independent root-bound U below P remains a positive control.

Preserved contexts still rewrite understood references, including closed/dormant payloads.
Only unavailable fragments are exempt. Allocation reuse requires both context preservation and
no actual reference rewrite. A known neighbouring change can allocate a new U while its complete
unknown component, owner, version and hidden defaults remain exactly equal under admitted work.
The original compiler supplies actual unavailable contributors before root aliases erase physical
custody; before/after matching also requires verified effective occurrence correspondence and the
same readiness reason.
