## Design Boundaries

Current independent gameplay crate separation does not itself prove a dependency defect. Test
debug-info or linker A/B only if final binary work dominates; compare Bevy's optional fast-build
configuration without copying a platform requirement into every project. Metadata/identity
caching needs exact environment invalidation. Executable copy/digest stages protect immutable
generations and races; do not remove them to shorten a graph.

Dynamic linking needs complete library publication, discovery and lifetime contracts beyond the
current executable/manifest generation. Native hot patching or another official author language
needs evidence under ADR 0093. Source receipts do not cover all Rust modules, build scripts,
environment inputs or proc macros; controlled source experiments cannot claim universal code
freshness. Root alone runs Cargo, one build job, shared target; no broad new benchmark framework.

The ignored `ordinary_rust_play_iteration_costs` consumer reuses existing ordinary Editor test
helpers, reads an explicitly supplied disposable external Collect Game, and writes separate JSON.
It does not create/delete projects. The public projection has no request nonce: clear the prior
result before dispatch, then require the next matching Applied operation and Running. Fresh Play
generations and reused Restart generations remain distinct. Root owns execution; the parallel
consumer lane owns only this private test child and its module declaration.
