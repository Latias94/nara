selected root itself, its understood components and its source-owned descendants. Replace that
branch in P with an instance of Q. Preserve effective transforms, component values, hierarchy,

## Owning Representation Problems

At the starting baseline, the [compiler layout](../../crates/nara_scene/src/prefab/overlay/compile/staged.rs)
mounted every Prefab's roots as children of a containing entity. Merely moving the selected record to
Q retains the old anchor and adds Q's root below it. This changes entity count, hierarchy and
transform composition. Renaming or ignoring the wrapper in an Editor panel cannot repair that
meaning.

At this unit's starting baseline, the neutral reference contained a document-local ID or a
persistent Runtime reference. Overlay sidecars had exact payload coordinates and typed occurrence
targets, but direct source records had no equivalent binding. Moving a local reference across
the cut could make its target unrepresentable. The selected inline reference language below
replaces that asymmetry. A global source-key substitution or preserving terminal ID spelling
does not establish the target.

The starting staged compiler retained one declared node scope/origin and one final entity provenance.
Root binding therefore required explicit canonical entity identity and contributor provenance,
including reference aliases and local-versus-inherited child order. Aliasing two arena
nodes to one materialized entity without those rules is not a complete root design.

There is also an owning-source ordering counterexample: P's root k binds Q, Q owns children d1
and d2, and P owns local child b under k. Ordinary editing of P must express d1, b, d2 without
moving b's declaration into Q or an instance-addition namespace. P's local-ID `children` list
cannot name d1/d2; k's overlay is interpreted in Q and cannot name P:b. An outer overlay over P
in another Scene cannot replace P's own authoring Interface. Resolve this together with root
binding, including whether source-owned typed placements replace the local-only source hierarchy
and lower into the existing flat materialized hierarchy.

### Source Placement And Flat Observation Interfaces

Scene and Prefab sources store an ordered `Vec<SceneEntityPlacement>` independently of their
entity records. Each declaration pairs an occurrence target with a `ScenePlacement` desired
parent and sibling slot. Overlay placements use the same type and layout kernel. Every directly
owned source entity requires exactly one declaration; an inherited target can have an additional
explicit source pin. Entity-map order never replaces a missing declaration. Raw admission checks
the local declaration shape without opening Prefabs; effective compilation alone proves routed
targets, canonical bases and the final normalized hierarchy.

Source transactions compare and replace complete placement declarations, including their stored
order. The inverse retains the complete old vector. Ordinary single-target pin and Revert helpers
construct that exact transaction; they do not replay historical moves to determine desired
layout. Adding or removing source records and their placements is one atomic batch, validated
against the complete result. Removing a declaration does not infer an effective visual subtree.

`PrefabInstanceBinding` explicitly selects `Forest` or `Root { base, root }`. Its canonical base
and typed entity target remain part of complete instance intent, including dormant declarations
and exact history snapshots. The serialized binding is required; source decoding does not infer
it from root count or preserve an older forest-only reader.

The root target uses `PrefabEntityTarget`, including canonical-checked routes and source/addition
origins. A qualified prerequisite's direct-ID root pin proved insufficient for complete extraction:
an outer instance can promote P:b to its sole root, then extraction moves b behind P:k into Q.
The rewritten placement can express `through[k@Q]/Source(b)`, but a root pin containing only b
cannot. A public before/after/forest control reproduced this refusal. Refine that prerequisite
inside the complete extraction unit; retain a finite root-demand cursor in actual cycle detection,
lookup before alias normalization, exact route costs and source-preserving copy/history semantics.

The compiler's temporary flat hierarchy is a private `SceneDraft`, with separate readonly
`ExpandedSceneEntity` observations. Authored records no longer carry compiled children, and an
authoring observation cannot be converted back into source merely by copying a document field.
Strict compiled storage and Native admission retain their already qualified independent owner.
Root aliases retain occurrence-local declaration facets, slots and lexical environments while
their final hierarchy, component batch and canonical provenance contain one entity. Source-facet
working storage and final materialized entity count have separate budget meaning.

## Reference Comparison And Selected Direction

Compare neutral occurrence references with Scene-owned direct-record bindings and explicit Prefab
inputs. A neutral reference must not pull Scene, Asset or source-file authority into Identity.
A Scene-owned binding must prove exact slot consumption and retain versioned payload/default
meaning. If a reusable Q refers outward, make that dependency explicit rather than hiding a lookup
in a compiler-generated entity name or allowing it to reconnect to another occurrence.

The selected design must cover internal, entering, leaving, nested and repeated references;
root self-references; optional/default values; dormant claims; detach/Revert and conversion-to-local.
Source preservation may retain an unresolved declared input, while activation must resolve every
required surviving reference or refuse specifically. Runtime publication receives fully resolved
references; authoring bindings cannot silently pass through a Native-only spawn path.

Also qualify the ordinary Inspector operation: P overrides an entity-reference property inside
its Q instance to point at P's own local b, while Q has no declared inputs and remains unchanged.
An operation target inside Q does not by itself select the new value's reference environment.
Keep this concrete requirement when selecting payload/input scope. The instance override must
be expressible without editing the reusable asset.

If bindings remain separate metadata, their versioned payload must own them atomically. A binding
map on an entity beside its component map allows a component replacement to leave stale reference
intent behind. Compare full-record binding ownership in `SceneComponentRecord` with the current
addition/Set-specific carriers, and define ordinary field-edit/default/migration behavior before
selecting it. Fewer declarations at the Interface matter more than retaining incumbent struct
fields. Separate source meaning from flattened Runtime references where that simplifies the owner.

Select inline authored reference values over persistent payload-coordinate sidecars. Two equal
`SceneLocal("socket")` placeholders can carry different targets in sidecars; swapping the bare
list values cannot express swapping those targets. A field's explicit Null can also hide a
reference-bearing default, for which a strictly consumed current-slot table has no entry. These
are value-language problems, not only metadata placement problems.

Use one component-value language for providers, Schema defaults, ordinary field/history operations
and source records. Lower the pure canonical source-key/ID/path values to Identity, keeping it
independent of Asset/App. Asset keeps actual metadata/path association; Scene keeps typed scope,
occurrence and input interpretation. Extend inline references with explicit authored targets and
declared input use, then remove the displaced addition/Set/property binding tables together.

The alternative generic reference-parameter value tree offers stronger leaf-type separation, but
also requires default/initial-value lifting, migration-domain conversion and source/opaque
representation bridges. A Rust1.95 metadata probe confirms that a default generic parameter alone
breaks unconstrained enum construction; concrete role aliases fix that inference issue but do not
remove the semantic conversions. Prefer one value language plus an owner-created flat compiled
boundary. This choice does not claim that extending an enum alone is Native-safe.

Flat compiled entities contain neither Prefab declarations nor unresolved authored targets/inputs.
All Native admission paths must reject surviving authored-only references after defaults and
before codecs or World mutation, including hand-written codecs and processed admission. Opaque
value contents and undeclared retained fields do not exempt typed authored-reference leaves
from that Native gate. Prove the complete effective value set before invoking its first codec;
an invalid later component must not let an earlier codec run. Source preservation/admission
retains its separate role and can keep authored values without claiming a Native result. Opaque
records stay complete in source preservation; neither their representation nor a pure key grants
interpretation, extraction or execution authority. Retain one shared Reflect walker and one Scene
compiler, with no second catalog or evaluator.

### Lexical Payload And Input Scope

Select one lexical source environment for every authored payload, contextual default and instance
argument. A P-authored overlay may target Q's entities, but its payload references still start in
that actual P occurrence. Structural target scope and value scope are separate facts. This
supports the ordinary instance override to P:b without adding inputs to the reusable Q asset.
Q's own outward dependencies remain declared inputs with explicit instance arguments.

Selected-base payload scope plus an explicit containing-source reference was a viable alternative.
It keeps shorter inherited-target spellings, but gives payloads different default environments
according to their container and adds a second scope qualifier. Prefer one lexical rule across
direct records, additions, pins and arguments; nested targets use explicit routes. This replaces
the incumbent binding-table scope rather than retaining a compatibility interpretation.

Reference syntax shares the existing canonical-checked occurrence route and has an entity-origin
or declared-input endpoint. Structural targets retain their entity-only endpoint role. A plain
Input(u) means the empty-route input endpoint in the payload's lexical environment; it has no
fallback to the selected base, parent or another occurrence with the same canonical key. An
explicit `through[a @ Q] / Input(u)` selects that actual Q occurrence's input environment.
This is one value language, with no second expression evaluator or implicit caller capture.

For the control P.u = P:c and P.a binding Q.u = P:b, Q's direct Input(u) resolves to b; a
P-authored overlay's plain Input(u) resolves to c. That overlay can explicitly select Q.u through
a's canonical route. Root binding preserves both declaration facets even when they share one
final entity. A selected nested instance claim retains its actual lexical declaration environment,
independently of the target overlay scope and final hierarchy.

Only surviving input uses demand their arguments. Arguments use their own lexical source scope,
so an argument can route back into the input being bound. Reject a cycle on the current resolution
chain keyed by actual occurrence and input ID, for example P.a's Q.u argument selecting
`through[a @ Q] / Input(u)`. Repeated completed bindings remain valid. Admit route traversal,
binding state and source demand within the existing finite compiler work/storage allowances.
Extraction remaps moved lexical declarations, including dormant values/defaults and arguments;
equal bytes in a different source do not prove equal reference meaning.

Whole-source copy preserves declared inputs as parameters. Its source-only request proves complete
source admission and remapping without inventing a separate mount for every supporting Prefab.
An actual consumer compiles the copied containing source with its real arguments and overrides.
Qualify P passing Q.u, Q copied alone as a parameterized source, and a source cycle terminated by
real outer intent. The wrong-base/missing-target/required-input/cycle controls belong to that
actual use; the copy owner must preserve their constraints without claiming activation eligibility.

Source-dependent reference defaults need explicit version/field-bound contextual declarations in
the authored record. They remain part of the complete tree even when an explicit value hides them.
Reset/Absent exposes that declared default; Revert resumes inheritance. Extraction rewrites their
outward targets to declared inputs without covertly changing omission into a value pin. Scalar,
Null and context-free Persistent defaults can continue using the canonical Schema template.
Schema succession must account for contextual defaults explicitly. Default editing retains field
capability and preservation constraints; this is not an alternate path around readonly fields.
