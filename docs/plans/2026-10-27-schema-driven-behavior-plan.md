# Schema-Driven Authored Behavior Comparison

## Missing Proof

The [first language slice](../research/2026-10-27-behavior-language-workflow-comparison.md)
compiles Mover/Sensor fields and event cases into its Rust harness. Successful embedding does
not prove that an author can install another Behavior without editing native extraction code.
Address this gap before promoting a runtime representation or selecting a language SDK.

## Bounded Replacement

Load an independently stored catalog through existing bounded `ComponentSchemaCatalog` file
admission. Compose its one owner with the real native provider through the existing authoring
basis. Keep source records in the existing Scene format. Do not duplicate catalog, property,
Prefab or reference validation in an adapter-specific interpreter.

The language module explicitly describes stable Schema/version callback bindings. Compare those
bindings with the admitted catalog before building a fresh private Runtime. Every selected
Schema must have exactly one matching binding; missing/duplicate/version-mismatched bindings
refuse new execution. Mere Schema availability still preserves source data.

Capture each selected record generically: enumerate its admitted stable root fields, resolve
through the existing property resolver and collect declared references through the existing
reference plan. The language sees owned typed field values and already-resolved native target
observations. Exact World/entity/Definition tokens remain outside the DTO. The single native
Name command remains a concrete domain, not a universal native dispatcher.

Add a third authored Label Schema with a stable field whose wire name differs. Both language
modules register its callback without a native Schema-ID switch. Add an optional Mover gain
field to this authored catalog, initially absent from the source, and observe changed values
without changing extraction logic. Refuse invalid catalogs/bindings and preserve a separate active
predecessor. A candidate's fresh World is not in-place migration or module replacement.

## Evidence And Limits

Run direct Scene and repeated Prefab occurrence data through actual C# and Lua callbacks. Edit
through prepared source operations and verify history, complete export identity and retirement.
Keep language-owned read helpers small and typed; they decode a finite value kind, not a second
Schema traversal language. Record the actual author changes needed for a new definition.

This remains a private fresh-Runtime comparison. It does not implement hot code replacement,
catalog lineage migration, actual assets, VM-local mutable state, arbitrary domain calls or a
public production SDK. Runtime body recompilation/restart, Schema data changes and owner
generation replacement are separate experiments. ADR 0120 remains Proposed.
