# Finite Source-Tool Property Facets

## Complete Consumer

Enable the independently built C# EnemyStats child in a prebuilt Editor. A small tool panel can
Attach or Spawn through the production Session. The ordinary Inspector replaces the actual
`health` row with the tool's admitted integer-parameter proposal control; `armor` retains the
generic editor. Panel and Inspector observe the same request/review, explicitly accept the same
prepared source candidate, receive the exact result and support one Undo/Redo, Save, physical
Close and fresh Open. Rust reads the same saved data. An old event after tool replacement or
disable must fail rather than target a successor activation. A missing facet restores the
generic field editor when source metadata remains admitted.

Nara's own custom-drawn Editor runtime remains the destination. The incumbent Dear frontend is
the concrete interaction oracle for this semantic boundary; no toolkit objects cross it. This
unit does not implement a widget-description tree, install/update system, new SDK, gameplay
publication or second document/Undo owner.

## Owning Correction

The finite process owner currently lives in Project Session, but its pure observations and
results also live in the root Host. Only a pending boolean reaches the immutable frame. Extending
the frontend directly would require another action/result queue or allow queued requests to
silently select the current activation. Fix those seams before adding controls.

Move source-tool observation, nominal IDs, finite intents, errors and commit receipts to the
existing `nara_tooling` crate. Keep trusted launch configuration, executable definitions,
process acquisition, Tasks custody and source preparation in Project Session. Add source-tool
actions/outcomes to the existing ordered Editor action/result vocabulary. Registered panels use
their existing submission/incarnation ledger; no parallel result bus is introduced. Remove the
root-owned duplicate types and pending-only frame projection directly, with no aliases.

The frame publishes the full immutable source-tool view. `active` carries the exact activation
ID plus immutable selected owner/component metadata and the optional finite property facet;
replace the redundant enabled boolean. Attempt and newest-request observations retain their
independent errors. Review remains borrowed from the Session's one prepared candidate; frames
carry bounded review observations, not a second prepared edit or inverse executor.

## Finite Facet And Actions

The actual child description may include one optional `integer_property` declaration: stable
root field, parameter key, input label and initial i64 parameter value. Admission checks finite
metadata and an editable i64 root in the selected component Schema. This is the exact capability
needed by EnemyStats health/bonus, not an open control taxonomy. There is no recursive layout,
callback, arbitrary action payload or child-supplied source identity. Update canonical protocol
1 in place; no previous-reader or response converter is required pre-release.

An ordinary request retains activation ID, original complete document-query basis, explicit
Attach/Edit/Spawn intent and bounded parameters. Replace the old direct request signature so
every deferred caller retains its execution basis. The specialized integer-property action
retains the same activation plus `EditorPropertyTarget` and one i64 parameter. The Session
rechecks the actual active declaration and uses its admitted parameter key. Acceptance consumes
the exact request's candidate. Disable carries the original activation so a late button cannot
disable its successor. Trusted enable remains a separate explicit Host configuration operation.
Cancelling an initial pending probe instead retains that exact attempt ID; it cannot cancel a
later probe or disable an unrelated active predecessor. There is no unqualified deferred stop.

Tool parameter drafts belong to the actual panel/control instance. Retire them on panel retirement,
activation replacement/disable, document incarnation/revision/Schema change or target change;
never refresh and replay old intent. Matching/default fallback uses admitted owner/component/
field metadata. Text, caret and IME remain frontend-owned. Painting only observes and queues
typed actions; mutation and execution admission happen after the paint borrow ends.
Ordinary dirty field input retains its existing independent recovery contract when hidden by a
facet. It never becomes the tool parameter and is not deleted by tool activation. Fallback may
show it for explicit recovery, including a source/Schema conflict; it never publishes automatically.

## Work Lanes And Verification

The parent owns the shared Tooling contract, frame/action integration, consumer migration,
frontend routing, ADRs and serial verification. Bounded workers may own the root process/facet
adapter, actual child metadata/consumer or isolated frontend controls after their API and
disjoint write sets are agreed. Reviewers remain read-only. No worker runs Cargo, formatting or
commits; all builds reuse root `target` with `CARGO_BUILD_JOBS=1`. Preserve unrelated changes and
`vendor/`; references remain read-only. Complete each owning replacement rather than retaining
the displaced transport for tests.

Qualify pure admission, old-activation actions, simultaneous observers and failed replacement
through window-free public owners. Exercise the actual C# declaration and mixed source data.
Frontend tests must operate the actual customized property and panel through the same ordered
submission ledger, including hidden/closed panel, replaced project, stale frame, old draft,
rejected request and default fallback. Native Windows/DX12 qualification must include the real
inline workflow and save/reopen, plus affected existing lifecycle trajectories. Record limits
separately from the future custom-drawn runtime or installation claim.

ADRs 0047/0118 own observation/action and finite facet admission; amend them before changing
those contracts. Proposed 0120 remains separate. The pinned Godot Inspector property contribution,
default property editor and independent dock registration inform the division of responsibilities;
Nara does not adopt its Object/Control model or global plugin list.
