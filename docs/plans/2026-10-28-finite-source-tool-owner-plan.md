# Project-Owned Finite Source Tool Proposals

The [qualification record](../knowledge/engineering/verification/2026-10/2026-10-27T180941Z-production-finite-source-tools-and-exact-physical-close-observations-fc2363973364434096d350ae4a8d762c.md)
owns executed scope, independent-review corrections and remaining boundaries. Completion applies
to this finite operation, not R1b/R3 or the complete foundation Goal.

## Decision And Complete Consumer

Implement the actual missing ordinary Editor boundary exposed by the EnemyStats experiment.
A trusted Host explicitly supplies one finite child command and its admitted declarative
component owner. The Project Session owns enable/probe, request, retained review, accept,
replacement/disable and physical retirement. Application delegates the same UI-neutral API.
The selected child receives copied values and returns a bounded property proposal. Document
identity, target/operation, original query basis, code-publication identity, newest request and
the owner-created prepared candidate never come from the returned payload.

Use the existing authoring Tasks activity for off-thread process acquisition, bounded pipe IO,
cancellation and physical return. A terminal cancellation is not physical completion. Session
Close retains the existing Runtime/Tasks owner until the child and all pipe workers return.
This first contract supervises one trusted direct child per finite invocation, not arbitrary
descendant trees or a sandbox. Keep incomplete cleanup pending and observable. No plugin
`Send + Sync` relaxation, second World/Undo store, universal language backend or SDK is needed.

The actual C# EnemyStats program is a separate executable and metadata artifact. It describes
the existing complete catalog before activation and supports Attach, edit and Spawn proposals.
The Rust Host verifies the entire expected catalog, and source requests additionally verify the
selected owner/component declaration against the original document admission. Keep gameplay
C#/.NET and Lua lifetime comparisons separate; remove the displaced in-process EnemyStats
tool bridge and fixture-owned proposal/review authority once the production consumer passes.

The launch value is explicit trusted Host configuration, not a project-authored permission or
an immutable executable package. Do not claim byte-pinned deployment, persistent installation,
dependency resolution, automatic startup discovery or an official C# SDK. A new activation has
its own exact process/publication identity even when a command path is reused. Existing source
metadata remains independently admitted when code is disabled; missing-metadata round-trip is
a separate source-authoring concern, not permission to execute.

## Ownership And Execution

The parent owns production protocol/Session state, integration, contracts and verification.
One worker owns finite process custody under the new Session module. Another owns the actual
C# child, runner and the independent consumer replacing the old EnemyStats fixture authority.
Writes are disjoint; workers do not run Cargo, format or commit. The parent runs Cargo serially
with `CARGO_BUILD_JOBS=1` and root `target`. An independent reviewer challenges code and lifecycle
boundaries before precise local commits and fast-forward integration. Preserve `vendor/` and
unrelated changes; no remote publication.

## Qualification

Run actual C# metadata/proposals through the public window-free Session and Application APIs.
Cover JSON/RON Attach/edit/Spawn, preview without mutation, exact result/created ID, one
Undo/Redo, Save, physical Close and fresh Open, plus Rust materialization/read of saved data.
Reject changed document/Schema, older request/publication, late invalid write, incompatible
candidate and malformed/oversized/nonzero child output. Failed candidates preserve the active
predecessor. Disable and Close revoke new work while retaining held spawn/IO responsibility
until actual return; late output cannot edit the successor. Verify lifecycle polling does not
run synchronous child waits or IO joins on the UI owner.

Use focused serial nextest, affected root/Editor/independent consumers, actual language runner,
feature-off/Clippy/format checks and appropriate Windows/DX12 native qualification. Record
passing scope and material gaps. This does not complete R1b/R3 or the full foundation Goal.
