# Installed Authoring Owner Adoption

## Consumer And Responsibility

Start an ordinary project without EnemyStats metadata. Capture and install its generation-one
finite release, explicitly review/adopt its non-executable owner, then enable the installed tool,
edit existing and new data, Undo/Redo, Save, physically Close and Open again. Open observes saved
selection without restoring execution approval. The incumbent frontend provides interaction
evidence; Nara's own custom-drawn Editor remains the destination.

This continues the full foundation rebaseline and the
[local lifecycle plan](2026-10-28-local-source-tool-release-plan.md). The durable selection unit
is independently qualified at `daead17`; it assumes metadata is pre-admitted. Adoption closes
that concrete premise. It does not implement installed dependency solving, safe removal, an
executable gameplay owner or catalog/value migration. Those remain required independent units.

Use the existing Project Session as coordinator, Reflect as bundle/declaration authority,
Scene/Prefab as classification/history owners and the shared file publisher as the file owner.
Do not add a Package Schema executor, parallel validator, universal document store or second
Undo system. Schema composition and executable approval remain independent.

## Exact Change

The first operation adds one previously absent persistent owner with a generation-one catalog
and no unresolved installed requirements. It retains every existing owner's complete current
and predecessor catalogs. `AuthoringSchemaBundle::new` remains the collision/lineage validator,
including current, predecessor and tombstone component claims. Equal existing content is an
explicit AlreadyAdmitted result; different content for an existing owner is not this operation.
Adding an owner does not advance other owners' generations or silently assign record owners.
AlreadyAdmitted requires the live Session and selected disk bundle to agree, not merely an owner
found on disk. A previously published-but-unadopted bundle requires explicit whole-live-set
reconciliation and a new review; dirty documents must not be discarded to regain that state.

Records, overlays, source identity and ordering are unchanged. Newly understood valid records
may become Available; wrong-owner, older/future and unrelated unknown records retain their
applicable classification. Known invalid values and invalid source-local EntityRef closure refuse
the prepared successor. Composed Prefab reference validation stays with the selected compiler;
asset existence and unresolved/degraded dependency policy stay with the Host capture owner.
Scene history proof does not establish asset availability. No value is repaired, default-persisted
or migrated by adopting metadata.
Source-semantic equality, rather than equality of the old unavailable manifest, proves preservation.

The source owners accept only a declaration extension: each prior selected current declaration,
persistent owner and Adapter evidence remains identical. The Host additionally proves complete
bundle owner/lineage preservation. A new shared `AuthoringSchemaBasis` is admitted once for the
successor and retained through document and project adoption; independently readmitting equal
bytes does not recreate that nominal basis.

## Dependency-Ordered Implementation

   bound to original source revision and exact previous basis. Classify the current source
   against the shared successor without replacing its Arc/document/source identity. Prepare
   every retained reachable Undo and Redo state through the existing patch preparation and
   scoped conversion rules. Extract a shared history-step preparation/cost kernel from actual
   replay; do not call ordinary prepared-edit entry points whose `history=false` rejects lawful
   owner-created RestoreEntity operations. For each edge, freeze the generated inverse, replay it
   under the same history scope and require exact source restoration and regenerated patch equality.
   Both directions must fit the originating entry's operation/value-node/logical-byte costs.
   If a legal operation has non-identical reverse spelling, explicitly bound or refuse that case;
   do not introduce a patch-equivalence interpreter. Traverse
   each branch from the current source, without publishing, allocating new history identities,
   running project callbacks or cloning a second history interpreter. Bound replay work and
   temporary retention explicitly using existing source/history accounting; exhaustion refuses
   before bundle publication. A narrow proof allowance must distinguish cumulative classification,
   replay and full-document-copy work from peak retained bytes. Charge current classification,
   every forward/reverse edge and full source-copy work before allocation. Account incumbent,
   retained successor classifications and current-edge scratch separately; do not retain one
   source snapshot per history entry or treat small patch bytes as a bound on large document scans.
   Commit changes classification only, preserving source revision,
   content-state identity, upgrade flag, history contents/cost, saved state and selection. Mark
   an existing Scene projection dirty. Old prepared edits/queries reject their old basis.
   This proves source replay, not eager activation of dormant overlay payloads. Preserve those
   payloads even when malformed in isolation. Current selected composition remains Host-owned
   and does not expand this source-history guarantee into all-history preview validity.
   A finite background request freezes exact current document/classification Arcs and retained
   patch/scope/cost entries. Charge the complete live incumbent set and owning history copy before
   allocation; no new source/content identities or temporary authoring Session are constructed.
   Owned and direct preparation share the same classification and history kernel. Prepared output
   pins its exact original document for further Host capture without borrowing live Workspace;
   original set/revision/basis revalidation is still required before exclusive publication.
2. **Bundle successor custody.** Prepare the composed bundle and ordinary engine-owned Adapters
   from code-free installation inspection. Reuse bounded bundle decoding/encoding and existing
   root/manifest observations. Add a narrow handoff from the actual admitted bundle leaf into
   `FilePublicationHost`, then from published leaf plus the same prepared bundle/basis into the
   successor project receipt. Prepare classification and actual source demand before publication;
   attach the actual accepted leaf after known publication without readmitting a second nominal
   basis. The ordinary startup-admission entry currently creates its own basis and cannot be
   called unchanged for this handoff. Do not downgrade live-object custody to native ID/digest alone.
   No new independent native registry or authoring Runtime is needed for this data operation.
   The successor must cover startup classification, retained Prefab source bases, actual assets
   and asset database, unresolved dependencies, source facts/stable lookups, readiness, diagnostics
   and budget usage. Rebuild or explicitly invalidate the source index bound to the old bundle
   leaf/digest. Capture uses the successor working copy of every already-open dirty Prefab.
   Keep startup's saved root and each dirty working root distinct. The original project snapshot
   is not a cache of the latest accepted Save: do not attach a new persistence digest to its old
   document or discard a working capture's revision to make it look like a saved startup root.
   Capture the actual saved startup through the existing source owner with the already admitted
   successor basis, or retain an exactly paired saved source/observation. A bounded fresh saved
   source read is allowed; a second nominal Schema admission and reopening live sessions are not.
   Share immutable published document/classification Arcs through existing Session construction
   instead of adding a duplicate source-snapshot representation or hidden fork deep copies.
   Current dirty captures retain their participant revisions; never seed them through the ordinary
   startup-preview initializer that assumes disk-only Prefabs and zero unsaved participants.
   Closed raw Prefabs retain actual-demand composition: do not force independent strict publication
   of a source whose invalid payload is lawfully repaired/discarded by an outer declaration.
   Capture actual current composition for the saved startup and each open Scene against the
   prepared working Prefabs. Preserve current semantic candidate/failure, diagnostics and unresolved
   facts for review. Capture uses ordinary Authoring admission: classified source failure, format,
   acquisition or budget errors refuse; a returned Degraded capture retains its typed composition
   failure, unresolved facts and preview limits without pretending it is ready for execution.
   Retained history must remain exactly source-replayable under the successor; it is not a promise
   that every past or cross-document combination can materialize. Later Undo/Redo selects current
   source again and uses ordinary revision-bound capture/diagnostics and repair. Do not add a second

3. **Whole open-set preparation.** Through Workspace, prepare every open Scene and Prefab,
   including inactive dirty documents, against that shared successor. Preserve per-document
   persistence Hosts and saved checkpoints. Capture the exact open set/incarnations, revisions,
   old basis and original project/bundle observations; review changes no source/history/file.
   Publish one whole prepared set, never a partial document-by-document schema transition.
   Workspace validates the complete set under exclusive access before an infallible classification
   swap; Session installs its matching project receipt in that same owner turn. There is no IO,
   callback or newly fallible admission between the first and final swap. Repeated per-document
   prepared-edit commits are not whole-set publication.
   Unsupported persistent extension owners must retain their authority or explicitly refuse
   this first operation; do not silently leave a contradictory project basis.
4. **Session publication and adoption.** Use existing finite Tasks and HostCustody. Conservatively
   refuse Busy while admitted Save/Reopen/Open, relevant import/conversion/tool/selection IO or

   preparation/retirement, fence new conflicting admissions and automatic restarts. Revalidate the original project,
   bundle, open set and each source before writing. After known publication, either atomically
   adopt the prepared project/document set or report PublishedWithoutAdoption. Close and stale
   admission cannot cause late adoption or activation. Refusal before writing retains incumbent;
   uncertainty retains actual evidence and requires explicit reconciliation. Do not roll back
   a published file automatically. Keep disk data, Session adoption and physical cleanup distinct.
   Admission uses concrete operation/retirement observations, not a requirement that every shared
   task queue or GPU frame be idle. Already admitted source capture must physically return or be
   retained and rejected by its old basis; ordinary View presentation can continue from immutable
   predecessor packets. An always-active renderer must not make metadata adoption permanently Busy.
   Invalidate old preview content stamps in the adoption owner turn. Source revision stays unchanged
   and the current stamp does not directly carry Schema basis, so a next-frame check is insufficient.
5. **Recipe refresh preservation.** The current schema refresh writes only the compiled recipe
   bundle. Make it preserve already admitted non-recipe owners and validate collisions through
   the same Reflect composition. Compiled recipe owners retain their explicit authority; a
   conflicting retained claim refuses before publication. Corrupt existing bundles cannot become
   permission to erase metadata. Adding an owner must survive the next ordinary Check/refresh;
   this does not automatically grant the owner a Runtime binding.
   Non-recipe means absent from this invocation's selected recipe, not a durable installed-owner
   category or provenance registry. If later explicitly selected by a compiled recipe, that owner
   follows the recipe's existing authority; collisions with other retained owners still refuse.
6. **Actual product qualification.** Use a genuinely missing-owner project, the independent C#
   installation consumer, Application and selected native adoption interaction. Keep tool approval

   relevant nextest/minimal/Clippy/native checks and commit a coherent checkpoint. Remove displaced
   shortcuts; keep the foundation Goal and the remaining lifecycle plan active.

## Source And History Counterexamples

### History preservation and current composition

Source truth and its disposable composition have different acceptance. ADR 0026 owns exact
source/inverse replay and retained cost; ADR 0047 explicitly permits a source repair while effective
composition remains rejected. An older authoring state can therefore be lawful source history
without being a usable preview. Metadata adoption preserves this same boundary.

The earlier requirement to prove every historical selected composition was an additional product
restriction, not a consequence of history preservation. Independent Undo/Redo can form a product
of Scene and demanded Prefab states; validating only separate axes is incomplete, while a complete
search can reject an otherwise useful adoption because of a past repaired conflict or combinatorial
work. Do not build a state-search engine to impose that extra guarantee. Retain the actual source
history proof, exact current dependency capture and explicit future composition failure/recovery.

Before publishing, prove every retained source edge in both directions through the existing kernel
and prepare current saved/open Scene roots with the actual selected current working Prefabs. No
independent Prefab root is invented. Unknown or native-binding omissions remain compiler-owned;
`Ok(Degraded)` or `failure == None` alone does not establish current semantic success. A returned
Authoring capture may preserve a composition conflict or unresolved dependency under the ordinary
degraded contract. Review and adopted observations retain those exact facts; no usable preview,
Play or Export authority follows. Source/format/acquisition/budget failures still refuse. The
Session integrates current facts with the full original source set, cumulative allowance and
publication fence, rather than adding a second complete-runtime gate to metadata recovery.

After adoption, an actual Undo/Redo publishes its admitted source transaction and invalidates
projection. The ordinary current capture then either publishes a new valid preview or exposes
composition diagnostics while retaining the last accepted preview under its existing stale-input
rules. Redo or an explicit source repair can restore composition; no history is removed, silently
rewritten or relabeled as saved. The guarantee is exact source-history continuity, not all-history
preview availability. A separate optional diagnostic tool would need its own concrete consumer
before any historical journal/search abstraction is added.

- Two Scenes and two Prefabs include inactive dirty sources, both Undo/Redo branches, saved states,
  unrelated unavailable records and dormant overlays. Exact source/selection/history survives
  adoption; newly understood data becomes editable without a fabricated source edit.
- An old explicit complete-instance repair hides a malformed unknown overlay value. Source-only
  classification must preserve this dormant history. With the real canonical base, prove current
  composition succeeds and a retained Undo/Redo state actually selects the invalid surviving
  value after adoption; source Undo/Redo still succeeds and actual current capture reports the
  conflict. Redoing the exact source repair restores valid composition. A paired outer replacement
  or suppression that lawfully discards the payload must succeed. Do not clear history, eagerly
  validate all embedded payloads or promise every past dependency combination will preview.
- A valid history patch generates an inverse which fails reverse admission under the successor.
  Reject that edge before publication; test RestoreEntity and scoped conversion through actual
  history semantics, not ordinary-edit restrictions.
- A valid unknown reference becomes a known dangling reference only in an Undo/Redo state.
  The existing reference checker must reject the prepared successor. No shadow reference walker.
- Old ordinary, construction and Prefab-conversion prepared values cannot commit after adoption.
  A source edit, branch/history change, document Close or replacement after review invalidates
  the retained set. Stale tokens cannot be repaired by silently refreshing their basis.
- Disk successor / live predecessor followed by a request for the same owner must not return a
  false AlreadyAdmitted. Explicit reconciliation prepares the current dirty set against the saved
  successor, then revalidates and adopts without replaying the stale original token.
- Native sessions without authoring metadata are not upgraded into generic authoring sessions.
  Existing native binding, Runtime selection and compiled schema agreement remain independent.
- History or source work budgets must reject pre-copy/replay rather than allocate unchecked
  snapshots for every entry. Record measured preparation cost; no unmeasured locality claim.

## Publication And Recovery Counterexamples

Exercise duplicate owners and reserved component claims, changed receipt/content, stale manifest
or bundle, exact-name/parent replacement, read-only project, known unpublished failure, held temp
cleanup, uncertain publication and successful disk publication refused by current Session state.
An external bundle rewrite is not permission to merge against fresh data behind an old review.

Hold Save/Reopen, preview capture, tool describe/proposal and selection publication at their real
physical boundaries. Verify Busy/cancel policy before writing, rejected late query/edit/review
tokens, Close before and after publication and abnormal Drop custody. Newly captured previews
carry the successor basis; old packets/receipts remain subject to their existing presentation
fences. Metadata-only records without a native preview Adapter remain explicit omissions.

Adoption does not transfer installer deletion authority to document data. Removing a tool later
must not erase adopted Schema, user-owned content or persisted values. Metadata adoption and
installed graph/removal can proceed as independent units and join in the final ordinary-install
workflow. Existing generation successors, executable publication cohorts, migration and missing
language restoration retain their separate foundation acceptance.

## Owning Contracts

ADRs 0090/0026 own classification recovery and retained history; 0047/0118 own whole open-set and
Session operation observations; 0114 owns authoring project successor admission; 0110 owns recipe
refresh. Amend those contracts before changing their boundary. ADR 0098 already distinguishes
owner-local lineage from composition. Neither adopting this operation nor its first source helper
adopts Proposed 0120 or completes a language SDK.

The [source-tool guide](../guides/finite-source-tools.md), ADR implementation ledger and immutable
engineering evidence must distinguish designed, source-only, public, actual installed and native
qualification. Do not add a migration guide, compatibility alias or old bundle reader.
