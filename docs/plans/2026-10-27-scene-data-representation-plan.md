# Production Scene-Owned Data Representation

## Objective And Contract

Implement the first production non-native data family through the
[Scene representation design](../architecture/scene-component-representations-design.md).
Replace the private preview/post-commit helper in a complete independent consumer; do not promote
its hidden entry points. Native registry cardinality, exact native preparation and strict
retirement remain intact. This is a prerequisite to actual optional-language owner integration,
not proof that R3 or the foundation Goal is complete.

The existing private code-lifetime checkpoint is `65402b9`. Backend-free owner metadata admission,
closed mixed selection/shared compilation and the production runtime-family successor are scoped
implementation slices. The [runtime evidence](../knowledge/engineering/verification/2026-10/2026-10-27T125421Z-production-scene-native-data-runtime-and-managed-authority-qualification-294f613511bb48e49fed958c05a1a469.md)
owns actual checks and remaining integration, rather than treating identified seams as execution.
The [product selection successor](../knowledge/engineering/verification/2026-10/2026-10-27T141025Z-mixed-scene-product-selection-and-content-to-runtime-admission-qualification-7c90588821aa4e8da374958ef2e436e4.md)
records recipe, strict content and managed startup/replacement integration. The private language
harness is replaced by the
[public Scene language consumer](../knowledge/engineering/verification/2026-10/2026-10-27T145608Z-public-scene-language-consumer-and-obsolete-representation-runtime-removal-67783a7cb8514ce9bbb7957670b4ec37.md).
The concrete language-owner/tool workflow remains next.
ADR 0006 adopts the closed native/data storage contract; ADR 0120 remains Proposed for broader
executable publication, language custody, migration and cohort replacement.

## Delivery Order

### Complete Binding And Compiler Path

Own Reflect metadata admission and Scene representation selection together with the first
consumer. Factor existing catalog/lineage/ownership checks for code-authored use without `serde`;
do not add a second Schema validator or expose an unused abstract extension SPI. Select explicit
native and data-only families, unique owner/type/tombstone claims and exact owner-local snapshots.
The shared Prefab compiler accepts this strict mixed authority and preserves complete source
provenance/actual demand. Do not compile runtime records through native-preview omissions.

### Atomic Production Materialization And Export

The [fixed-baseline runtime review](../audits/2026-10-27-scene-runtime-and-extension-plan-review.md)
adds three shared native prerequisites: compose plugin-owned authority guards at existing App
safe points; require exact managed definitions through advanced replacement as well as ordinary
prepare while preserving independent projections; and reject export definitions that omit actual
live native persistent members. Implement these in their owning paths rather than a data-only
workaround.

Prepare complete per-entity data groups with native prepared values before target allocation.
Insert the concrete pure-data carrier through the existing validated insertion tail, reserving
its type against product overlays. Add exact data-definition capture alongside existing native
World/managed checks. Runtime full-value member replacement/removal validates Schema/references
before mutation and preserves siblings.

Extend the existing current-live export loop and aggregate allowance for both families. Reject
native-only export of encountered data records rather than omitting them. Preserve existing
persistent-reference semantics and strict retirement, including native claims and additional
retirements. No fallible post-native-commit carrier installation or cached initial entity roster.
Data export separately lowers Schema-declared asset references through selected immutable
metadata under `Path` and `StableIdWhenKnown`; it does not inherit policy from native codecs or
the entity-reference rewrite. Test matching native/data output, nested references and unavailable
required conversion metadata with no partial output or asset loading.

### Independent And Managed Consumers

Run a public no-serde code-authored consumer plus a file-backed Scene/Prefab consumer. Cover
two data Schemas on one entity with native Name, source Attach/Edit/Undo/Save/Reopen, repeated
Prefab references, complete export after entity population changes and whole-instance retirement.
The consumer must not import `__private`, forge native bindings, or construct provenance manually.

Then admit the same definition through the actual managed App startup/recipe path and migrate
the selected optional owner away from the private helper. Materialization of plain data is not
language execution readiness: required callback/module contributions still reject when absent.
Select one production optional-language path using domain access and author-workflow evidence;
do not turn both experimental bridges into maintained SDKs for optionality.

Include an actual scheduled Rust data consumer: read and replace one member, preserve its sibling,
reject a command retaining a retired entity incarnation, and keep runtime writes out of source
history. The initial family may expose conservative carrier-level ECS access/change granularity;
per-Schema dynamic descriptors require independent query/scheduler pressure. Share this consumer
with the later semantic tool/inline Inspector workflow without freezing a toolkit panel API.

### Product Selection And Language Consumer Sequence

Product contributions retain admitted owner snapshots. One complete selection passes through
`SchemaValidationInput`, strict content capture/Check, installed World authority and all startup
or replacement entries. Project-backed `SceneSource` must retain its exact metadata-only witness
even when consumed through public direct startup; a Host-only comparison is insufficient.
Outer group edits cannot orphan a data declaration from its contributing plugin. Native known
owner claims remain reserved against selected data owners, including inactive tombstones and
immediate predecessor claims. Source declaration compilation precedes effective asset capture;
rejected surviving records are reported by that compiler rather than an early native-only reader.

The language fixture now consumes the public Scene selection/preparation/access/export path and
the real window-free Project Session. Its old preview/post-commit runtime and cached export
helper are deleted. Keep its concrete C# experiment and actual
collectible-context/held-callback evidence; existing Lua tests may share the corrected harness
without becoming a second production SDK program. Preserve complete callback ID/version admission,
atomic command rejection, execution-publication fencing and physical code-retirement observation.
Do not use Authoring preview or a fallible post-commit carrier installation for runtime storage.

Use the existing public window-free Project Session for source edits/history and Save/Reopen;
an empty authoring-adapter receipt list does not make known-unbound fields editable. Superseded
representation correctness consumers now map to production/public tests, with a new guarded
setter negative for a retired reference target. Two raw storage probes retain query/orphan
counterpressure; they do not measure the production carrier or throughput. Historical
measurements do not justify retaining a second Runtime.

The [concrete EnemyStats experiment](2026-10-27-enemy-stats-semantic-tool-plan.md) now returns
limited semantic proposals to that same Session owner. The Host retains source basis, executable
publication and newest-request custody, prepares the edit and consumes that candidate once.
Real JSON/RON history/persistence and public Rust reads exercise Attach, edit and Spawn. Nara's
custom-drawn frontend can later consume the same command/result path.
This order requires no universal language backend, new generic transaction executor, toolkit
embedding or official C# SDK designation. Install/update/disable, held tasks and delivery still
need their own complete workflow evidence.

Keep compiled Editor visual authoring coverage explicit. Its native preview and native
Apply Changes exporter are still separate consumers; mixed runtime startup does not establish
editable data records or mixed Apply Changes in that lane. Use the complete metadata-based
Session consumer for the next language/tool workflow, then replace any remaining native-only
authoring assumptions at their owning boundary. Do not silently omit data records in a live
export or promote a preview capability into project execution authority.

## Verification And Removal

Use focused serial nextest with root `target` and `CARGO_BUILD_JOBS=1`, then affected Scene/Reflect,
root and independent consumers. No-default coverage must prove the code-authored family is not
accidentally gated on `serde`. Reuse native identity/retirement and aggregate budget tests rather
than replacing them with positive examples. Add exact last-record, late-hook, wrong-basis,
missing-module, foreign World, native-only export and stale membership counterexamples.

Require independent review of the production diff and public workflow. Actual Editor/runtime
changes need their affected native qualification; a headless family test alone cannot claim it.
After complete replacement, remove the superseded private grouped-materialization/export helper
while retaining only indispensable losing-alternative evidence with a durable report. No old
reader, alias or migration guide is required. Commit locally in coherent verified units without
remote publication. Keep implementation scope and remaining R3/foundation obligations explicit.
