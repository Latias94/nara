## Complete Consumer

Run a prebuilt executable from a verified immutable local Runtime base with only processed
catalogue, Scene and Input members and normal platform libraries. No source manifest, sidecar,
cache, source tree or Cargo is available to that child. Drive normalized keyboard/mouse input,
observe actual semantic gameplay effects, cancel/restore contexts and travel A-to-B-to-A without
reinstalling global Input. Reject missing, malformed or mismatched members and competing code
configuration before Startup. Keep the original running World on rejected travel.

## Selected Boundaries

1. `nara_project::RuntimeInputConfiguration` carries an optional complete primary action-map
   Product. Its admitted Runtime value contains no source path. Source projection retains its
   existing unfulfilled path separately and does not silently convert it to a Product.
2. `nara_input` owns `ActionMapAsset`, its `ActionMapDomain` and a strict `runtime_action_map`
   version-one codec. Source and processed files share finite declaration compilation and
   structural decoding, while their envelope kinds remain distinct and reject each other.
   The processed asset has a complete primary Product, immutable definition and explicit empty
   Required-reference inventory. It has no source identity record, filesystem or native handles.
3. The original executable recipe selects the concrete codec and frozen limits through the
   existing Runtime codec agreement. A requested startup Input requires the actual Input plugin
   and a selected decoder for that typed family. Catalogue membership validates the requested
   Product and expected runtime kind independently of Scene roots and addressable travel rights.
4. Startup acquires the selected global Input once through the original base and actual typed
   codec. Its retained handle keeps the actual `RuntimeContentAsset<ActionMapAsset>` and original
   acquisition charge. Independent World state reserves its own allowance from that same base.
   Reuse Input's existing candidate-scope receiving operation before Scene materialization and
   Startup. No shared mutable map, detached product copy or source importer is introduced.
5. Global startup Input custody is independent of Scene domain collections and replacement.
   Later Scene preparation and commit do not replace that owner or recreate its World-local state.
   Explicit Scene Required references may independently acquire the same Product as typed CPU
   data with their own original-base charges; those reads grant no global installation authority.
   Escaped bindings preserve their original base/output charge until their last owner drops;
   queued/held identities retain
   the original independent state ticket after resource replacement or shutdown observation.
6. When no Product is selected, explicit code-first Input remains valid. Explicit empty code configuration
   competes with a selected processed map just as it does with source selection. Runtime
   configuration/data cannot select executable code or manufacture decoder authority.

Reconcile ADRs 0035/0041/0051 and the existing Runtime base contract before their production
boundaries change. Keep target-build selection separate: this unit builds its proof executable
through the existing trusted test invocation, not a new build system or a Runtime Cargo call.
