# Godot headless scene/data consumer

This ordinary GDScript project generates and consumes actual `PackedScene` `.tscn`
files through public Godot APIs. It requires no engine build, extension, imported
assets, custom resource class, or editor import pass. The intended runner is the
official Godot 4.7.2-stable Windows console executable, supplied by the caller.

Run from the repository root in PowerShell:

```powershell
$fixture = (Resolve-Path 'docs/benchmarks/fixtures/runtime_scene_comparison/godot').Path
$output = Join-Path $env:TEMP 'nara-runtime-scene-comparison-godot'
& 'F:/MySoftware/Godot-4.7.2-stable/Godot_v4.7.2-stable_win64_console.exe' --headless --path $fixture --script main.gd -- $output
```

The sole argument after `--` is an owned absolute output directory, or a `user://`
directory. The script creates it and overwrites only its nine deterministic
`godot-<mode>-<rows>.tscn` files. External absolute `.tscn` paths are passed directly
to `ResourceSaver` and `ResourceLoader`; no copy into `res://` is required.
There is no build step. Success exits with code 0 after nine JSON records, one per
mode and population. Failed checks print an error and request exit code 1, with
explicit returns rather than debugger-dependent GDScript assertions. Godot's
startup banner may also appear on stdout; retain JSON object lines for JSONL.

Populations are 64, 4,096 and 16,384, with `side = sqrt(rows)` and each row equal
to `{x: i % side, y: i / side, tile: i % 64, flags: i % 4}` using integer division.
The checksum is the integer sum of every field: 2,560, 393,216 and 2,621,440.
Every warmup and sample also checks all four fields of every row outside timers.

| Mode | Saved representation | Scope |
| --- | --- | --- |
| `generic_dictionaries_one_node` | One `Node`, persistent `cells` metadata containing an array of dictionaries | Primary generic scene/data consumer |
| `native_variant_packed_int32_one_node` | One `Node`, persistent `cells` metadata containing a `PackedInt32Array`, four values per row | Primary compact native Variant collection; no TileMapLayer |
| `native_tile_map_layer_restricted` | One `TileMapLayer`, actual `tile_map_data` generated by `set_cell` | Additional restricted native tile storage comparison |

Each mode receives three warmups followed by nine retained samples. JSON arrays
report nanoseconds converted from `Time.get_ticks_usec()`; resolution is 1,000 ns,
so very small operations can report zero. The phases are:

- `warm_read_ns`: `FileAccess.get_file_as_bytes`, including open, read and close;
  no String decoding. Generation and an initial size read warm the OS file cache.
- `utf8_decode_ns`: conversion of those bytes to a String. This diagnostic phase
  does not feed `ResourceLoader`, which independently reads the file.
- `decode_ns`: actual `ResourceLoader.load(path, "PackedScene", CACHE_MODE_IGNORE)`.
  This includes another file read, UTF-8/text parsing and PackedScene construction.
  It is not an isolated in-memory decode; do not subtract the warm-read timing.
- `instantiate_ns`: actual `PackedScene.instantiate()` creating the root outside
  the tree, including property application and the native cell-store setter.

Generation, packing, saving, validation, cleanup, printing and process startup are
outside the phases. `source_bytes` is the actual `.tscn` file length. There are no
external dependencies or attached scripts. No compile phase is synthesized.
Metadata arrays can share storage with the loaded PackedScene under Godot's
Variant semantics; instantiation does not force a deep copy of collection data.

The TileMapLayer maps `tile` to atlas coordinate `(tile, 0)`, `flags` to alternative
ID and uses source ID 0. These identifiers preserve this finite workload; flags
are not arbitrary metadata or a claim about rendered tile transformations. There
is no TileSet, texture, tree entry, deferred tile update, collision or navigation.
Validation enforces the real used-cell count, all expected cell identifiers and
the native serialized length of a 2-byte header plus 12 bytes per cell. This is
not a RAM estimate; native hash maps and object overhead are outside that count.
Native coordinate/identifier widths are narrower than the metadata modes.

`--headless` selects Godot's headless display/dummy renderer. The fixture measures
CPU-side file/scene/data work and makes no actual-GPU performance claim.
API and native-layout inspection used `git show` in the read-only `repo-ref/godot`
checkout at exact Godot 4.7.2-stable commit
`ed1daf0bf001b61586d9930840f2f1394092c079`, including
`scene/2d/tile_map_layer.cpp`. The checkout's 4.8-beta HEAD was not changed.
The caller supplied and verified the official binary identified as
`4.7.2.stable.official.ed1daf0bf`. Each record includes `Engine.get_version_info()`;
the caller owns execution, binary provenance evidence and measured results.
