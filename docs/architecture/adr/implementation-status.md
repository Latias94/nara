# ADR Implementation Status

**Status**: Active
**Last Verified**: 2026-08-02

This ledger tracks implementation evidence independently from ADR decision acceptance. Its sole active execution contract is the [startup scene activation and atomic Retry plan](../../plans/2026-08-02-001-refactor-startup-scene-activation-and-atomic-retry-plan.md), which preserves completed RGS-U1 through RGS-U3 evidence while carrying the stopped Retry workflow under `SRT-U<N>`. Superseded plans remain audit evidence and trigger backlog, not active implementation authority.

## Schema

| Field | Contract |
|---|---|
| Decision | `proposed`, `accepted`, `superseded`, or `rejected`; must mirror the ADR file. |
| Implementation | `not-started`, `partial`, `implemented`, or `superseded`. |
| Owner | Crate or architecture domain, never a person. |
| Plan unit | The unit that owns the next evidence transition. |
| Code anchors | Existing repository paths and stable symbols. Required for `partial` and `implemented`. |
| Verification anchors | Existing test/configuration/evidence paths. Required for `partial` and `implemented`. |
| Remaining gap | Required for `not-started` and `partial`. |
| Trigger | Required for `not-started` and `partial`; states the evidence needed for transition. |
| Last verified | Date and commit whose repository state was inspected. |

`implemented` requires at least one code/configuration anchor and one verification anchor, with no remaining gap or trigger. The validator derives exact ADR/catalogue/ledger membership, proves anchor paths, and checks symbols on RGF-touched rows; reviewers still own the semantic judgment that those anchors cover the whole decision. `not-started` must not invent anchors. New ADRs are added by their owning unit before code is changed.

## Proposed Admission Decisions

These rows track high-cost candidate decisions. Proposed ADRs do not override Accepted decisions or
become product guarantees. An active plan may explicitly perform a bounded evidence-producing trial
named by the proposal, but code existence does not change decision status; a separate admission
review must verify the trigger and promote the ADR before its new contract becomes authoritative.
