This ledger tracks implementation evidence independently from ADR decision acceptance. It initially covers ADRs touched by the engine-foundation completion plan; U20 completes non-blocking classification of the remaining historical ADRs.

## Schema

| Field | Contract |
|---|---|
| Decision | `proposed`, `accepted`, `superseded`, or `rejected`; must mirror the ADR file. |
| Implementation | `not-started`, `partial`, `implemented`, or `superseded`. |
| Owner | Crate or architecture domain, never a person. |
| Plan unit | The unit that owns the next evidence transition. |
| Code anchors | Existing repository paths and stable symbols. Required for `partial` and `implemented`. |
| Verification anchors | Existing test/configuration/evidence paths. Required for `partial` and `implemented`. |
| Remaining gap | Required for `not-started` and `partial`. |
| Trigger | Required for `not-started` and `partial`; states the evidence needed for transition. |
| Last verified | Date and commit whose repository state was inspected. |

`implemented` requires at least one code/configuration anchor and one verification anchor, with no remaining gap or trigger. The validator proves paths and shape; reviewers still own the semantic judgment that those anchors cover the whole decision. `not-started` must not invent anchors. New ADRs are added by their owning unit before code is changed.
